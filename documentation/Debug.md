# Введение

Обработка неперехваченных ошибок и инструменты разработчика. Пакет находится в `Expansa\Debug`,
доступ к нему — через фасады `Debug` и `Panel` и хелперы `dump()`, `dd()`, `metrics()`.

```php
use Expansa\Facades\Debug;
use Expansa\Facades\Panel;

Debug::configure(view: EX_DASHBOARD . 'debug.php', details: Is::debug(), report: fn (Throwable $e, string $id, array $context) => ...);
Debug::register();

$id = Debug::report($e);            // в лог, вернёт id ошибки: 7f3a9c1e
Debug::handle($e);                  // в лог и страница ошибки
Panel::add('Cache', fn () => ['hits' => 12, 'misses' => 3]);

dump($user, $request);              // читаемый дамп
metrics()->time();                  // 12.4ms
```

| Класс     | Назначение                                                                          |
|-----------|-------------------------------------------------------------------------------------|
| `Manager` | Обработчики PHP-ошибок, исключений и фатальных ошибок; отчёт и вывод ошибки; экземпляр фасада `Debug` |
| `Panel`   | Debug-панель: секции-таблицы, собираются при выводе; экземпляр фасада `Panel`        |
| `Dumper`  | Дамп значений для `dump()` и `dd()`                                                 |
| `Metric`  | Время с начала запроса и память; экземпляр хелпера `metrics()`                      |
| `Internal\Page` | Данные ошибки для страницы, JSON и консоли; маскирование секретов; только для `Manager` |

Объект ошибки, который возвращают вместо результата (`error('user-find', ...)`), — это `Expansa\Support\Error`.

## Конфигурация

`Debug::configure()` вызывается в `bootstrap.php` до фаз, сразу после `Is::configure()`: тогда ошибка
в любой фазе попадает в лог и на страницу. Без конфигурации ничего не логируется, а ошибка выводится
простым текстом.

```php
Debug::configure(
    view: EX_DEBUG['view'],
    details: Is::debug(),
    report: fn (Throwable $e, string $id, array $context) => Log::error('Uncaught {class}: {message}', [
        'id' => $id, 'class' => get_class($e), 'message' => $e->getMessage(), 'exception' => $e,
    ] + $context),
    warning: fn (ErrorException $e) => Log::warning('{message} in {file}:{line}', [...]),
    context: fn () => [
        'method' => $_SERVER['REQUEST_METHOD'] ?? '',
        'user'   => fn () => App\Models\User::current()?->id,
        'input'  => $_POST,
    ],
    json: fn () => str_starts_with(Route::uri(), '/api/'),
    editor: EX_DEBUG['editor'] ?? '',
    collapse: [EX_CORE, EX_PATH . 'vendor/'],
);
Debug::register();
```

| Параметр   | Что задаёт                                                                     |
|------------|--------------------------------------------------------------------------------|
| `view`     | Шаблон страницы ошибки; без него — простой текст                               |
| `details`  | Показывать сообщение, код, трассировку и запрос; только в режиме отладки       |
| `report`   | Куда записать ошибку: получает исключение, id и контекст                       |
| `warning`  | Куда записать PHP-предупреждение, после которого запрос продолжается          |
| `context`  | Данные запроса для лога и страницы; значение-`Closure` вычисляется отдельно    |
| `json`     | Отвечать ли JSON; без колбэка решает заголовок `Accept`                        |
| `editor`   | Ссылка на код с `{file}` и `{line}`: `vscode://file/{file}:{line}`, `phpstorm://open?file={file}&line={line}` |
| `collapse` | Папки, кадры из которых свёрнуты на странице: ядро, vendor                     |

В `env.php` ссылки на код включаются через `EX_DEBUG['editor']`, запись в лог отключается через
`EX_DEBUG['log'] = false`.

## Обработка ошибок

`register()` перехватывает всё, что не поймал `Lifecycle::run(catch:)`:

- **Исключения** вне `run()` — в обработчике `terminate`, в отложенных хуках. В консоли процесс
  после этого завершается с кодом 255, как без обработчика.
- **Фатальные ошибки** — нехватка памяти, превышение `max_execution_time`, ошибка компиляции.
  Их видит только shutdown-функция; она регистрируется изнутри другой shutdown-функции и поэтому
  выполняется последней, после отложенных хуков. После нехватки памяти она поднимает `memory_limit`
  на 8 МБ, чтобы вывести страницу: резерв памяти, который держал бы каждый запрос, не нужен.
- **Предупреждения и notice.** В режиме `details` они становятся `ErrorException` и останавливают
  запрос, иначе уходят в `warning`, и запрос продолжается. Deprecated всегда уходят в `warning`.
  Одно место (`уровень:файл:строка`) уходит в `warning` один раз за запрос: предупреждение в цикле
  или в чужом коде не забивает лог. Ошибки под `@` и уровни вне `error_reporting()` пропускаются.

Вывод ошибок самим PHP (`display_errors`) отключается: ошибку выводит `send()`.

У каждой ошибки свой id из 8 символов. Он попадает в лог (`report`), на публичную страницу и в
JSON-ответ: посетитель сообщает id, а запись в логе находится по нему. Ошибки API в `App\Http\Kernel`
проходят через `Debug::report()` и тоже получают id.

Если упал сам `report`, обе ошибки записываются в `error_log()`, а страница всё равно выводится.

`Manager::isFatal($e)` отличает фатальную ошибку от остальных: `bootstrap.php` пишет такие в лог
уровнем `critical`, остальные — `error`. Так на нехватку памяти, таймаут и ошибку компиляции можно
настроить отдельное оповещение, например канал Telegram с `level: critical`.

## Страница ошибки

`send()` отдаёт статус 500. В консоли текст пишется в STDERR, для JSON-запроса — `{ "message", "id" }`,
у HEAD-запроса тела нет, иначе подключается шаблон `view` с переменными:

Перед выводом сбрасываются буферы, открытые после `register()`, и буфер `output_buffering` самого PHP:
в них недорисованная страница. Вывод, который уже ушёл клиенту без буфера, вернуть нельзя.

Если упал сам шаблон, выводится текст в `<pre>`: id, а в режиме `details` ещё ошибка и сбой шаблона.

| Переменная  | Что содержит                                                         |
|-------------|----------------------------------------------------------------------|
| `title`     | Класс исключения; без подробностей — `Server Error`                  |
| `message`   | Сообщение; без подробностей — общий текст                            |
| `id`        | Id ошибки в логе                                                     |
| `file`, `line`, `link` | Место ошибки и ссылка на него в редакторе                 |
| `trace`     | Кадры `file`, `line`, `call`, `code`, `start`, `link`, `collapsed`; первый — место `throw` |
| `arguments` | Аргументы вызова, упавшего с `TypeError`: `position`, `type`, `value` |
| `previous`  | Предыдущие исключения: `title`, `message`, `file`, `line`, `link`    |
| `request`   | Контекст запроса, секреты скрыты                                     |

Без подробностей заполнены только `title`, `message` и `id`: посетитель не видит ни кода, ни путей,
ни сообщения исключения.

У каждого кадра свой фрагмент кода: 10 строк до и после. Кадры из папок `collapse` свёрнуты в группы,
место `throw` не сворачивается никогда. Трассировка ограничена 50 кадрами.

Контекст скрывает значения ключей, похожих на секреты (`password`, `token`, `api_key`, `cookie`,
`csrf`, `session` и другие), во вложенных массивах тоже, и для лога, и для страницы.

Шаблон экранирует все значения сам и не использует переводы, хуки и фасады: ошибка могла произойти
в них. Строки страницы — на английском.

## Debug-панель

В режиме отладки `App\Listeners\Debug` добавляет панель внизу каждой страницы дашборда. Секции:
`Metrics`, `Timeline` (шаги `Lifecycle`), `Queries` (все запросы `Db::log()`: в режиме отладки
`Db::configure()` получает `logging: true`, кроме консоли, где долгий процесс копил бы запросы) и
`Request`. Стили — `css/debug.css`.

Плагин добавляет свою секцию:

```php
Panel::add('Cache', fn () => [
    ['key' => 'options', 'hit' => true],
    ['key' => 'menu', 'hit' => false],
]);
```

Колбэк возвращает список строк (`колонка => значение`) или пары `имя => значение`. Вызывается он при
выводе панели, поэтому видит весь запрос; если колбэк упал, секция покажет его ошибку.

`add()` не заменяет секцию с тем же заголовком, чтобы плагин не затёр секцию ядра. Чтобы заменить,
сначала вызовите `Panel::forget('Queries')`. `getSections()` возвращает собранные секции, `render()` — HTML.

## Дамп

```php
dump($value, $other);  // каждое значение отдельным блоком
dd($value);            // дамп и exit(1)
```

В браузере дамп выводится экранированным `<pre class="debug-dump">`, в консоли — текстом. Свойства
объектов отмечены видимостью: `+public`, `#protected`, `-private`. Вложенность больше 6 уровней
и рекурсия обрезаются, строки — после 1000 символов. Если у объекта есть `__debugInfo()`, используется он.

## Замеры

```php
metrics()->time();          // время с начала запроса: 12.4ms, 1.25s
metrics()->time(true);      // в секундах, float
metrics()->memory();        // пик памяти скрипта: 4.12MB
metrics()->memoryUsage();   // память, выделенная у системы сейчас
metrics()->memoryPercent(); // пик выделенной памяти в процентах от memory_limit, null без лимита

metrics()->start();         // начать отсчёт заново, чтобы замерить одну операцию
```

Отсчёт начинается с `REQUEST_TIME_FLOAT`, поэтому в него входят запуск PHP и автозагрузка.

## Производительность

`php tests/benchmarks/Debug.php` — что пакет добавляет к каждому запросу (PHP 8.4, opcache выключен):

| Случай          | Время, мкс | Что измеряется                                          |
|-----------------|-----------:|---------------------------------------------------------|
| `configure()`   | 1,2        | Новый `Manager` и конфигурация как в `bootstrap.php`    |
| `register()`    | 2,7        | То же и регистрация обработчиков                        |
| warning, PHP    | 0,1        | Повторное предупреждение без обработчика                |
| warning, once   | 0,45       | Повторное предупреждение, уже отправленное в `warning`  |

Пакет новый, поэтому бенчмарк сравнивает не с прошлым коммитом, а с отсутствием обработчика.
Дорогое вынесено из запроса в обработку ошибки: `realpath()` папок `collapse` (было 25 мкс на запрос)
и резерв памяти для нехватки памяти (около 20 мкс на холодном процессе).
