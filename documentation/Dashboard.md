# Dashboard

Страницы дашборда открываются по slug: `dashboard/site-health` показывает шаблон `screens/site-health`, а данные
для него готовят поставщики, зарегистрированные на этот slug. Ядро регистрирует свои страницы тем же API,
что и плагины, поэтому плагин меняет и дополняет любую страницу ядра:

```php
use App\Facades\Dashboard;
use Expansa\Http\Request;

Dashboard::page('orders', can: 'orders_read', title: fn () => t('Orders'));
Dashboard::data('orders', fn (Request $request) => ['orders' => Order::latest($request->getInt('page', 1))]);
```

| Класс                         | Назначение                                                      |
|-------------------------------|-----------------------------------------------------------------|
| `App\Facades\Dashboard`       | Фасад: `page()`, `data()`, `render()`                           |
| `App\Dashboard\Manager`       | Реестр страниц и поставщиков, вывод страницы с 403 и 404        |
| `App\Dashboard\Core`          | Страницы самого дашборда, регистрируются до загрузки плагинов   |
| `App\Dashboard\Pages\*`       | Поставщики данных страниц ядра: `User`, `FieldGroups`, `SignIn`… |

## Страница

Страница без регистрации тоже открывается: достаточно шаблона `dashboard/views/screens/<slug>.blade.php`.
`page()` нужен, когда у страницы есть право, свой заголовок или другой шаблон, например шаблон плагина:

```php
Dashboard::page('user', can: 'users_edit');
Dashboard::page('users', view: 'screens/edit');                   // тот же шаблон, что у edit
Dashboard::page('orders', view: __DIR__ . '/views/orders');      // шаблон плагина: абсолютный путь без расширения
Dashboard::page('edit', view: fn (Request $request) => $request->getString('table') === 'files' ? 'screens/media' : 'screens/edit');
Dashboard::page('orders', title: fn (array $data) => $data['order']->number);
```

| Опция   | По умолчанию                       | Что делает                                                  |
|---------|------------------------------------|-------------------------------------------------------------|
| `view`  | `screens/<slug>`                   | Шаблон: имя, абсолютный путь или замыкание от запроса       |
| `can`   | право пункта меню на эту страницу   | Без права — страница 403                                    |
| `title` | подпись пункта меню, иначе slug    | Строка или замыкание от данных страницы; к нему добавляется имя сайта |

Повторный `page()` меняет только переданные опции, остальные остаются: плагин может сменить заголовок
страницы ядра, не зная её шаблона и права.

Заголовок лучше передавать замыканием: страницы регистрируются на каждом запросе, в том числе к API, а
замыкание переводится, только когда страница открыта.

## Данные

Поставщик возвращает переменные шаблона. Их может быть несколько на один slug: результаты объединяются,
и каждый следующий получает данные, собранные до него.

```php
// ядро
Dashboard::data('user', App\Dashboard\Pages\User::data(...));

// плагин: заказы на странице пользователя, с пользователем из ядра
Dashboard::data('user', fn (Request $request, array $data) => ['orders' => Order::forUser($data['user'])]);

// на всех страницах
Dashboard::data('*', fn () => ['announcement' => App\Models\Option::get('dashboard.announcement')]);
```

- Порядок: по `priority` (меньше — раньше, по умолчанию `10`), при равном — `*`, затем в порядке регистрации.
- Ключ из более позднего поставщика заменяет ранний. `page` и `title` заняты лейаутом и не перезаписываются.
- Поставщик бросает `Expansa\Http\Exceptions\NotFound` (текст попадёт в `$message` страницы 404) или
  `Expansa\Access\Exceptions\AccessDenied` — вместо шаблона откроется 404 или 403.
- Данные готовятся, только когда страница открыта и право проверено: для чужих они не считаются.

Шаблон получает только готовые данные и описывает их в шапке через `@var`; запросов, `$_GET` и
`new` в нём нет.

## Вывод

`Web::index()` приводит адрес к slug и вызывает `Dashboard::render($slug, $request, $layout)`:
лейаут `welcome` для дашборда, `guest` для страниц входа и установщика. `render()` проверяет право страницы и пункта
меню на неё, наличие шаблона, собирает данные и заголовок, а при ошибке выводит `403` или `404` с
нужным статусом. Готовый HTML проходит через хук `dashboardLoaded`.

## Шаблоны

```
dashboard/views/
  welcome        лейаут панели: полный HTML-документ с шапкой, меню, диалогами и местом под содержимое
  guest          лейаут входа, регистрации и установки
  screens/       содержимое по slug — то, что лейаут вставляет в середину: user, settings, sign-in…
  components/    переиспользуемые блоки, которые вставляются куда угодно
    form/        поля конструктора форм
    table/       ячейки и шапка таблиц
    dialogs/     содержимое диалогов
    menu, search, notifications, state…
  mails/         письма
  fallback/      страницы ошибок на чистом PHP, без Blade: отладка (debug) и неподходящий сервер (error)
```

Полный HTML есть только в лейаутах `welcome` и `guest`. Лейаут получает `page` — имя шаблона экрана — и выводит его с теми
же данными: `view($page, $__data)`. Экран не знает, в каком лейауте он показан, а компонент — на каком экране.

`fallback/` — не шаблоны Blade, а самостоятельные PHP-страницы: `error.php` показывается на старом PHP
до загрузки остального кода, `debug.php` — при ошибке, которая может случиться в самом шаблонизаторе.
