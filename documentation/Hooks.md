# Введение

Хуки Expansa позволяют создавать и отслеживать различные события, происходящие в приложении.
Такое поведение в программировании иногда называется перехват. Но в рамках экосистемы Expansa 
их принято называть хуками. Другими словами, хуки, — это участки кода которые позволяют 
переопределить или расширить стандартное поведение приложения.

Например, вот распространённый сценарий. Необходимо отправлять уведомление в Telegram 
пользователю каждый раз, когда создан новый заказ в магазине. Вместо того чтобы нагромождать код 
обработки заказа с кодом уведомления, вы можете создать хук, в котором прикреплённый слушатель 
добавляет код отправки уведомлений.

## Создание новых хуков

Используя фасад Hooks, вы можете вручную регистрировать события в любом доступном вам месте 
приложения. В качестве значений возможно передать неограниченное число переменных, которые 
будут доступны слушателю.

```php
<?php
use Expansa\Facades\Hook;

Hook::call('testHook', $var1, $var2, ...);
```

## Создание новых слушателей

Для создания новых слушателей доступны несколько подходов.

### #1. Добавление через обычную callback функцию

```php
use Expansa\Facades\Hook;

function applyTestHook($var) {
    $var = 'foo';
    return $var;
}

Hook::add('testHook', 'applyTestHook');
```

### #2. Добавление через анонимную функцию

```php
use Expansa\Facades\Hook;
use Expansa\Hooks\Attributes\HookListenerAlias;

Hook::add('testHook', fn(&$var) => $var = 'foo');
// или
Hook::add('testHook', #[HookListenerAlias('applyTestHook')] fn(&$var) => $var = 'foo');
```

Анонимная функция без псевдонима не имеет постоянного идентификатора, поэтому убрать её через 
`flush()` нельзя. Псевдоним, установленный через аттрибут `HookListenerAlias`, даёт анонимной 
функции такое же стабильное имя, каким для обычной функции служит её имя — по нему слушателя 
можно снять точно так же, как если бы это была обычная функция:

```php
Hook::flush('testHook', 'applyTestHook');
```

Поэтому при разработке рекомендуется использовать второй подход.

### #3. Добавление через сканирование каталога с PHP классами

По умолчанию Expansa автоматически ищет и регистрирует ваши слушатели событий, просканировав 
каталог Listeners. Когда Expansa находит (!внимание) **публичный метод класса** слушателя, Expansa 
регистрирует эти методы как слушатели для хука. При этом, название метода должно соответствовать
названию хука.

```php
\Expansa\Facades\Hook::configure(GRFM_CORE . 'Listeners');

// file app/Listeners/Test.php
<?php
class Test
{
	public function testHook($var) {
		$var = 'foo';
		return $var;
	}
}
```

Не беспокойтесь, если вы не видите этот каталог в своей теме или плагине. Вы можете создать их
вручную. В будущем, мы предложим способ генерировать события и слушателей с помощью команд консоли.

Класс слушателя создаётся не в момент сканирования каталога, а лениво — только когда один из его 
хуков реально сработает в первый раз, и затем переиспользуется для всех последующих вызовов. 
Поэтому большой каталог `Listeners` с редко используемыми слушателями ничего не стоит, пока эти 
хуки не понадобились.

Повторный вызов `configure()` для уже просканированного каталога или файла безопасен — файл не 
сканируется заново, и слушатель не регистрируется дважды. Если же класс слушателя не может быть 
создан (например, объявлен как `abstract`), `configure()` бросит `HooksException` с понятным 
сообщением, а не невнятную ошибку рефлексии.

## Изменение приоритета слушателей

Один хук может иметь несколько слушателей, которые не зависят друг от друга. Если мы хотим 
контролировать последовательность выполнения для таких случаев, используется параметр приоритет. 
Приоритет - это просто числовое значение: чем оно выше, тем раньше оно выполняется.

Если слушатель подключается через метод `add`, приоритет указывается в 3 параметре метода. В 
данном примере, функция `commerceProductCreate` сработает раньше `commerceProductUpdate`, несмотря
на то что она зарегистрирована позже.

```php
<?php
use Expansa\Facades\Hook;use Expansa\Hooks\Priority;

Hook::add('testHook', 'commerceProductUpdate', Priority::BASE);
Hook::add('testHook', 'commerceProductCreate', Priority::HIGH + 1);
```

Если слушатель подключается через каталог `Listeners`, номер приоритета указывается через PHP 
аттрибут `HookListenerPriority`, где 400 - число приоритета:

```php
use Expansa\Hooks\Attributes\HookListenerPriority;

class Test
{
	#[HookListenerPriority(400)]
	public function testHook($var) {
		$var = 'foo';
		return $var;
	}
}
```

Если у метода одновременно есть аттрибут `HookListenerPriority` **и** приоритет передан явным 
3-м параметром в `add()` (например, при ручном добавлении `[$object, 'method']`), побеждает 
аттрибут — явный параметр в этом случае будет проигнорирован.

## Одноразовые слушатели

Если слушатель должен сработать только один раз, а затем автоматически перестать 
отвечать на хук, используйте `once()` вместо `add()`. Он принимает те же аргументы:

```php
use Expansa\Facades\Hook;

Hook::once('testHook', function ($var) {
    // выполнится только при первом вызове call('testHook', ...)
    return $var . '-once';
});
```

## Сброс всех хуков

Хранилище хуков общее на весь процесс. `reset()` очищает все зарегистрированные хуки, а также 
внутренний кэш `configure()` (что позволяет пересканировать уже обработанные каталоги заново). 
Пригодится в первую очередь в тестах, чтобы хуки, зарегистрированные одним тестом, не 
просачивались в следующий:

```php
use Expansa\Facades\Hook;

Hook::reset();
```

## Просмотр зарегистрированных хуков

Команда консоли `hooks:list` выводит таблицу со всеми зарегистрированными хуками: имя хука, 
приоритет, слушатель, файл:строка, где он был добавлен, и сколько раз хук уже реально сработал 
за этот процесс — удобно, чтобы понять, кто и откуда слушает конкретный хук, не прибегая к поиску 
по коду:

```bash
php artisan hooks:list
php artisan hooks:list testHook
```

Для слушателей, найденных через `configure()`, в качестве "откуда добавлен" показывается файл и 
строка самого метода в классе-слушателе — а не место, откуда был вызван `configure()`.

## Выгрузка хуков плагина или темы

`flushSource()` снимает разом все хуки, которые были зарегистрированы из конкретного файла, или, 
если передать каталог — из любого файла внутри него. Это способ откатить всё, что успел 
зарегистрировать плагин или тема, если их отключили в рантайме, не отслеживая вручную каждое имя 
хука и каждого слушателя:

```php
use Expansa\Facades\Hook;

// Снять всё, что зарегистрировал конкретный плагин
$removed = Hook::flushSource(EX_PATH . 'plugins/telegram-notifier');
```

Источник, по которому идёт сравнение — то же самое место, что показывает `hooks:list` в колонке
"Registered at": место вызова `add()`, либо, для слушателей из `Listeners`, файл самого класса.

## Проверка, сработал ли хук

`calls()` возвращает, сколько раз хук был реально вызван через `call()` — в отличие от `get()`, 
который считает *слушателей*, а не *вызовы*. Удобно в тестах, чтобы убедиться, что событие вообще 
произошло, и в отладке — понять, почему хук как будто бы не срабатывает:

```php
use Expansa\Facades\Hook;

Hook::call('orderCreated', $order);

if (Hook::calls('orderCreated') === 0) {
    // хук ни разу не был вызван за этот процесс
}
```

## Отложенное выполнение

Некоторые слушатели выполняют побочный эффект, который не должен задерживать ответ пользователю — 
например, отправку уведомления в Telegram из примера в самом начале этого документа. `defer()` 
ставит вызов хука в очередь и выполняет его уже после того, как ответ отправлен клиенту (через 
`register_shutdown_function()` и, если доступно, `fastcgi_finish_request()`), а не сразу же:

```php
use Expansa\Facades\Hook;

Hook::defer('orderCreated', $order);
```

Поскольку слушатель выполняется уже после отправки ответа, его возвращаемое значение никому не 
достаётся — используйте `call()`, если слушателю нужно вернуть значение, от которого зависит 
вызывающий код.

## Соглашение об именовании хуков

В рамках разработки плагинов и тем, рекомендуется придерживаться соглашения об именовании хуков: 
использовать `префикс` + `название метода` в camelCase формате. Например: `commerceBeforeCreateOrder`.
Именование без префикса допускается только в рамках использования ядра Expansa. Не используйте 
однословные названия хуков. Пусть название отражает его целевое назначение.

Такой подход предотвращает конфликты имен в крупных проектах, упрощает работу для инструментов
анализа кода и поиска по подстроке, а также инструментах генерации документации.

В названии динамических хуков используйте фигурные скобки для переменных:

```php
// правильно:
\Expansa\Facades\Hook::call("commerceUpdate{$status}{$post}");

// неправильно:
\Expansa\Facades\Hook::call('commerceUpdate' . $status . $post);
```

Также, в PHP комментариях к динамическому хуку рекомендуется писать возможные варианты 
конкретного имени хука. Формат такой записи выглядит так:

```php
/**
 * Possible hook names include:
 *
 *  - `commerceUpdateNewProduct`
 *  - `commerceUpdateOldOrder`
 *  - `commerceUpdateDraftPage`
 */
\Expansa\Facades\Hook::call("commerceUpdate{$status}{$post}");
```
