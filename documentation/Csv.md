# Введение

`Csv` читает и пишет CSV по RFC 4180: поля в кавычках могут содержать разделитель, кавычки и
переносы строк. Кодек сам определяет кодировку, разделитель и перенос строк, поэтому файлы из
Excel, Google Sheets и 1С обычно читаются без настройки. Для кодировок, которые нельзя определить
автоматически (например, китайской GBK), её передают явно.

Работать можно через фасад `Expansa\Facades\Csv` или напрямую с классом `Expansa\Codecs\Csv`.
Состояния у кодека нет, так что оба варианта равноценны.

```php
use Expansa\Facades\Csv;

$rows = Csv::decode('/path/to/file.csv'); // [['id', 'title'], ['1', 'Hello']]
$csv  = Csv::encode($rows);               // "id,title\r\n1,Hello"
```

## Чтение

`decode()` принимает путь к файлу или содержимое CSV. Строка считается путём, если в ней нет
переноса строки и такой файл существует.

```php
Csv::decode('/path/to/file.csv');
Csv::decode("name;price\nNike;100"); // [['name', 'price'], ['Nike', '100']]
```

Результат — список строк, каждая строка — список значений. Все значения возвращаются строками,
пустые строки файла пропускаются. Заголовок специально не выделяется: это первая строка результата.

### Большие файлы

`decode()` держит весь результат в памяти: около 30 МБ на 50 тыс. строк. Для больших файлов и
для случаев, когда нужны только первые строки, используйте `iterate()`. Он возвращает генератор
и читает файл построчно, поэтому расход памяти не зависит от размера файла.

```php
foreach (Csv::iterate($filepath) as $row) {
    Post::add($type, array_combine($map, $row));
}

$header = Csv::iterate($filepath)->current() ?? []; // только первая строка
```

Файл закрывается сам, когда цикл закончился или был прерван через `break`.

### Автоопределение формата

У `decode()` и `iterate()` одинаковые необязательные параметры: `$delimiter`, `$enclosure`,
`$linebreak` и `$encoding`. По умолчанию все они равны `'auto'`.

| Параметр | `'auto'` | Как определяется |
|---|---|---|
| `$delimiter` | `,` `;` `\t` `\|` | тот, что даёт больше всего колонок во всех первых 10 строках |
| `$enclosure` | `"` | не определяется: одинарную кавычку нужно передать явно |
| `$linebreak` | `\r\n` `\n` `\r` | тот, что встречается чаще всего |
| `$encoding` | UTF-8, Windows-1251 | по BOM, а без него — UTF-8, если файл валиден в ней, иначе Windows-1251 |

Всё это определяется только по первым 64 КБ файла. Если в них одна латиница, а кириллица в
кодировке Windows-1251 начинается дальше, файл будет прочитан как UTF-8. В таком случае укажите
кодировку явно.

Если формат известен, передайте его явно: это надёжнее и немного быстрее.

```php
Csv::decode($filepath, ';', '"', "\n");
Csv::decode($filepath, encoding: 'Windows-1251');
```

### Кодировка

Результат всегда в UTF-8, на любом языке: кириллица, китайский, японский, арабский и эмодзи
читаются без потерь, если кодировка определена правильно.

Автоматически распознаются только UTF-8, UTF-16 с BOM и Windows-1251. Остальные однобайтовые и
восточноазиатские кодировки (GBK, Big5, Shift_JIS, EUC-KR, KOI8-R и другие) принимают почти
любые последовательности байт, поэтому надёжно отличить их друг от друга нельзя. Без явного
`$encoding` такой файл прочитается как Windows-1251, и вместо текста будут кракозябры:
`ХЕО°` вместо `张伟`.

Если файл пришёл не в UTF-8, передайте кодировку явно:

```php
Csv::decode($filepath, encoding: 'GBK');           // упрощённый китайский (Excel в Китае)
Csv::decode($filepath, encoding: 'BIG5');          // традиционный китайский
Csv::decode($filepath, encoding: 'CP932');         // японский (Excel в Японии)
Csv::decode($filepath, encoding: 'EUC-KR');        // корейский
Csv::decode($filepath, encoding: 'KOI8-R');        // старые русские системы

foreach (Csv::iterate($filepath, encoding: 'GB18030') as $row) {
    // ...
}
```

Принимается любое имя, которое понимают и mbstring, и iconv, в любом регистре. Имя передаётся
как есть: например, `CP932` не заменяется на `Shift_JIS`, иначе потерялись бы символы расширения
Microsoft вроде `①` и `髙`.

- **Если у файла есть BOM, он главнее `$encoding`.** BOM однозначно задаёт кодировку, поэтому
  файл с UTF-8 BOM прочитается как UTF-8, даже если передано `encoding: 'GBK'`.
- **Неизвестное имя** (`encoding: 'nope'`) выбрасывает `InvalidArgumentException`. У `decode()`
  это происходит сразу, у `iterate()` — на первой итерации, как и всё чтение в генераторе.

Кодировка применяется потоковым фильтром, поэтому на скорость и память `iterate()` она не влияет.

Для файлов от пользователей давайте выбрать кодировку в форме загрузки, с вариантом «Авто» по
умолчанию: автоопределение тут в принципе ненадёжно. Так сделано в импорте постов в дашборде:
список кодировок лежит в `App\Api\Files\FilesService::CSV_ENCODINGS`, а значение из запроса
проверяется через `FilesService::csvEncoding()` — всё, чего нет в списке, превращается в `'auto'`.

## Запись

`encode()` принимает список строк и возвращает CSV-строку в UTF-8 без BOM и без переноса строки
в конце. По умолчанию разделитель `,`, кавычки `"` и перенос `\r\n`, как ожидает Excel.

Excel открывает UTF-8 без BOM в локальной кодировке системы, поэтому кириллица и иероглифы
превращаются в кракозябры. Если файл будут открывать в Excel, добавьте BOM в начало:

```php
$csv = "\xEF\xBB\xBF" . Csv::encode($rows);
```

`decode()` и `iterate()` такой BOM распознают и срезают.

```php
Csv::encode([
    ['id', 'title', 'price', 'draft', 'meta'],
    [1, 'Say "hi", ok', 9.5, false, null],
    [2, "multi\nline", 0, true, ['a' => 1]],
]);
// id,title,price,draft,meta
// 1,"Say ""hi"", ok",9.5,0,
// 2,"multi
// line",0,1,"{""a"":1}"
```

Значения, которые не являются строками, приводятся так:

| Значение | В CSV |
|---|---|
| `null` | пустое поле |
| `true` / `false` | `1` / `0` |
| число, `Stringable` | строковое представление |
| массив, объект | JSON |

Ключи внутри строки игнорируются, важен только порядок значений. Поэтому ассоциативные массивы
(например, строки из БД) можно передавать как есть, а заголовок добавить отдельно:

```php
Csv::encode([array_keys($posts[0]), ...$posts]);
```

Кодек не защищает от CSV-инъекций. Если файл откроют в Excel, а значения пришли от
пользователей, строки, начинающиеся с `=`, `+`, `-` или `@`, нужно экранировать до вызова
`encode()`.

## Производительность

Замеры на PHP 8.4, файл на 50 тыс. строк по 8 колонок (9,5 МБ):

| Операция | Время | Пиковая память |
|---|---|---|
| `decode()` | 181 мс | 30,8 МБ |
| `iterate()` | 176 мс | 0,2 МБ |
| `encode()` | 44 мс | 10,1 МБ (размер результата) |
