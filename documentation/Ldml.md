# Введение

`Ldml` переводит форматы дат между PHP `date()` и шаблонами Unicode LDML (Locale Data Markup
Language, [TR35](https://unicode.org/reports/tr35/tr35-dates.html#Date_Field_Symbol_Table)).
LDML — стандартный формат шаблонов дат. Его понимают date-fns (`format()`), Luxon (`toFormat()`),
ICU и PHP `IntlDateFormatter`, а его подмножество — многие календари, в том числе Air Datepicker.

Кодек нужен там, где формат задаётся один раз в PHP (например, в настройках сайта), а даты
показываются и на сервере, и в браузере. Переводится **формат**, а не сама дата:
`'d.m.Y'` ↔ `'dd.MM.yyyy'`.

Работать можно через фасад `Expansa\Facades\Ldml` или напрямую с классом `Expansa\Codecs\Ldml`.

```php
use Expansa\Facades\Ldml;

Ldml::encode('F j, Y \a\t H:i');         // "MMMM d, yyyy 'at' HH:mm"  PHP → LDML
Ldml::decode("d MMMM, yyyy 'at' HH:mm"); // 'j F, Y \a\t H:i'          LDML → PHP
```

## Соответствие токенов

| Что | PHP | LDML | Пример |
|---|---|---|---|
| день с нулём | `d` | `dd` | 03 |
| день | `j` | `d` | 3 |
| день недели, кратко | `D` | `EEE` | Wed |
| день недели | `l` | `EEEE` | Wednesday |
| месяц с нулём | `m` | `MM` | 04 |
| месяц | `n` | `M` | 4 |
| месяц, кратко | `M` | `MMM` | Apr |
| месяц | `F` | `MMMM` | April |
| год | `Y` | `yyyy` | 2024 |
| год, две цифры | `y` | `yy` | 24 |
| часы 0–23 / 00–23 | `G` / `H` | `H` / `HH` | 14 |
| часы 1–12 / 01–12 | `g` / `h` | `h` / `hh` | 2 / 02 |
| минуты | `i` | `mm` | 06 |
| секунды | `s` | `ss` | 05 |
| миллисекунды | `v` | `SSS` | 123 |
| микросекунды | `u` | `SSSSSS` | 123456 |
| AM/PM | `A` | `a` | PM |
| часовой пояс | `e` | `VV` | Europe/Moscow |
| смещение | `O` / `P` / `p` | `xx` / `xxx` / `XXX` | +0300 / +03:00 / Z для UTC |
| ISO 8601 | `c` | `yyyy-MM-dd'T'HH:mm:ssxxx` | 2024-04-03T14:06:05+00:00 |
| RFC 2822 | `r` | `EEE, dd MMM yyyy HH:mm:ss xx` | Wed, 03 Apr 2024 14:06:05 +0000 |

При обратном переводе понимаются и равнозначные поля LDML: `y`, `yyy` (год), `L…LLLL` (месяц в
именительном падеже), `E`, `EE`, `eee`, `ccc` (день недели), `aa`, `aaa`, `Z`, `ZZ`, `ZZZ`,
`ZZZZZ`.

Перевод проверен на ICU 75 (`IntlDateFormatter`): 736 сравнений в четырёх часовых поясах, вывод
совпадает с `date()` символ в символ в обе стороны. Названия месяцев и дней в LDML берутся из
локали форматтера, поэтому совпадение с `date()` гарантировано только для английской локали.
PHP `date()` всегда выводит их по-английски.

ICU и JS `Date` хранят время с точностью до миллисекунд, поэтому `SSSSSS` выведет `123000`
вместо `123456`. Это ограничение форматтеров, а не перевода.

## Текст в формате

В LDML все латинские буквы зарезервированы под поля, а текст берётся в одинарные кавычки.
Апостроф записывается как `''`. Кодек делает это сам:

```php
Ldml::encode('d/m/Y \a\t H:i');        // "dd/MM/yyyy 'at' HH:mm"
Ldml::encode("G \o'\c\l\o\c\k");       // "H 'o''clock'"
Ldml::decode("h 'o''clock' a");        // "g \o'\c\l\o\c\k A"
Ldml::encode('d.m.Y г.');              // 'dd.MM.yyyy г.' — не латиница, кавычки не нужны
```

## Что нельзя перевести точно

**PHP → LDML:**

| PHP | Что это | Нестрогий режим |
|---|---|---|
| `a` | am/pm строчными | `a` (выведет PM, прописными) |
| `T` | аббревиатура пояса (MSK) | `z` (ICU выведет GMT+3) |
| `W`, `o` | ISO-неделя и её год | `ww`, `YYYY` (в LDML неделя зависит от локали) |
| `S`, `N`, `w`, `z`, `t`, `L`, `U`, `B`, `I`, `Z`, `X`, `x` | суффикс «st», номера дней, число дней в месяце, метка времени и др. | удаляется |

**LDML → PHP:**

| LDML | Что это | Нестрогий режим |
|---|---|---|
| `m`, `s` | минуты и секунды без нуля | `i`, `s` (с нулём) |
| `z`, `zz`, `zzz` | короткое имя пояса | `T` |
| `w`, `ww`, `Y`, `YYYY` | неделя и год недели | `W`, `o` |
| `G`, `Q`, `k`, `K`, `EEEEE` и другие | эра, квартал, часы 1–24, узкие названия | удаляется |

Удаляемый токен убирается вместе с разделителем рядом, поэтому формат остаётся аккуратным, без
висящей запятой: `N, d.m.Y` → `dd.MM.yyyy`.

### Строгий режим

Если точность важнее, например при сохранении пользовательского формата, передайте
`strict: true`. Тогда кодек выбросит `InvalidArgumentException` со списком всех токенов без
точного соответствия:

```php
Ldml::encode('jS F Y', strict: true);
// InvalidArgumentException: Cannot convert date format: PHP token "S" has no exact LDML equivalent.

Ldml::decode('H:m', strict: true);
// InvalidArgumentException: Cannot convert date format: LDML field "m" has no exact PHP equivalent.
```

## Пример: формат из настроек в браузере

```php
$dateFormat = $options['date-format'] ?? 'F j, Y';   // PHP-формат из настроек

echo date($dateFormat, $timestamp);                  // на сервере
$pattern = Ldml::encode($dateFormat);                // 'MMMM d, yyyy' — для JS
```

```js
import { format } from 'date-fns';

format(new Date(), pattern); // 'April 3, 2024'
```

Air Datepicker понимает LDML не полностью: у него `aa` вместо `a`, нет секунд, и текст в кавычках
не поддерживается. Для него можно либо адаптировать шаблон на стороне JS, либо передать в опцию
`dateFormat` функцию, которая форматирует дату LDML-библиотекой.

## Производительность

Около 5 мкс на `encode()` и `decode()`: для формата, который переводится один раз на страницу,
этого достаточно.
