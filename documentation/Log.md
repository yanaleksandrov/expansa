# Введение

Логирование по [PSR-3](https://www.php-fig.org/psr/psr-3/): сообщение с уровнем и контекстом
записывается в файл, отправляется в Telegram или в `error_log()`. Пакет находится в `Expansa\Log`,
доступ к нему — через фасад `Log`.

```php
use Expansa\Facades\Log;

Log::info('User {name} signed in', ['name' => $user->login]);
Log::error('Payment failed', ['order' => $id, 'exception' => $e]);
Log::channel('telegram')->critical('Database is down');
```

| Класс                              | Назначение                                                              |
|------------------------------------|-------------------------------------------------------------------------|
| `Manager`                          | Каналы из конфигурации, создаются при первом обращении; экземпляр фасада |
| `Logger`                           | Канал: имя, обработчики, общий контекст                                 |
| `Level`                            | Уровни от `Debug` до `Emergency`                                        |
| `LogRecord`                        | Одна запись, неизменяемая: её получают все обработчики канала           |
| `Handlers\*`                       | Куда писать: файл, файл по дням, Telegram, `error_log()`                |
| `Formatters\*`                     | Как записать: строка или HTML-сообщение Telegram                        |
| `Exception\LogException`           | Неизвестный уровень, неверная конфигурация, файл нельзя открыть         |

## Конфигурация

Каналы объявляются в фазе `configure` (`bootstrap.php`). По умолчанию это один канал — файл
на каждый день, `storage/logs/expansa-2025-01-31.log`, файлы хранятся две недели:

```php
Log::configure([
    'daily' => [
        'driver' => 'daily',
        'path'   => EX_STORAGE . 'logs/expansa.log',
        'days'   => 14,
        'level'  => Is::debug() ? 'debug' : 'info',
    ],
]);
```

`configure(array $channels, string $default = '')`. Канал по умолчанию — `$default` или первый
в списке, в него пишут `Log::info()` и остальные методы фасада. Повторный вызов заменяет
конфигурацию и сбрасывает уже созданные каналы. Пока `configure()` не вызван, записи уходят в
`error_log()`.

| Драйвер    | Параметры                                    | Обработчик          |
|------------|----------------------------------------------|---------------------|
| `single`   | `path`, `level`                              | `File`              |
| `daily`    | `path`, `days` (7, 0 — хранить все), `level` | `RotatingFile`      |
| `telegram` | `token`, `chat_id`, `level` (`error`)        | `Telegram`          |
| `errorlog` | `level`                                      | `ErrorLog`          |
| `stack`    | `channels`                                   | обработчики каналов |

`level` — минимальный уровень канала, по умолчанию `debug`. Записи ниже него отбрасываются сразу,
без форматирования.

```php
Log::configure(
    channels: [
        'daily'    => ['driver' => 'daily', 'path' => EX_STORAGE . 'logs/expansa.log', 'days' => 14],
        'telegram' => ['driver' => 'telegram', 'token' => '123:abc', 'chat_id' => '@alerts', 'level' => 'critical'],
        'all'      => ['driver' => 'stack', 'channels' => ['daily', 'telegram']],
    ],
    default: 'all',
);
```

Папка `storage/logs` закрыта от веба: для Apache — `storage/logs/.htaccess`, для
`php artisan serve` — проверка в `server.php`. На nginx закройте её сами:

```nginx
location ^~ /storage/logs/ { deny all; }
```

## Уровни

| Уровень     | Значение | Когда                                                     |
|-------------|---------:|-----------------------------------------------------------|
| `emergency` |      600 | Система неработоспособна                                  |
| `alert`     |      550 | Нужно действовать немедленно: сайт или база недоступны     |
| `critical`  |      500 | Критическая ошибка: упал компонент, неожиданное исключение |
| `error`     |      400 | Ошибка, не требующая немедленной реакции                  |
| `warning`   |      300 | Нештатная ситуация, не ошибка: устаревший API             |
| `notice`    |      250 | Обычное, но значимое событие                              |
| `info`      |      200 | Интересное событие: вход пользователя                     |
| `debug`     |      100 | Отладочная информация                                     |

Уровень принимается в любом виде: `Level::Error`, `'error'`, `'ERROR'`, `400` или код RFC 5424
от 0 до 7 (`3`). Неизвестный уровень выбрасывает `LogException`.

```php
Log::log('warning', 'Disk is almost full');
Log::channel('daily')->isHandling('debug');   // false, если уровень канала выше
```

## Сообщение и контекст

Плейсхолдеры `{key}` заменяются значениями контекста: строки и числа как есть, `true`/`false`/`null`
словами, даты в RFC 3339, исключения как `Класс: сообщение`, массивы и объекты как `[array]`,
`[ClassName]`. Плейсхолдер без значения остаётся как есть.

Контекст целиком записывается в строку лога JSON'ом. Исключение (по соглашению — в ключе
`exception`) записывается с классом, сообщением, кодом, файлом и строкой, и с предыдущими
исключениями:

```
[2025-01-31 10:20:30] daily.ERROR: Payment failed {"order":15,"exception":{"class":"RuntimeException","message":"Timeout","code":0,"file":"/app/Pay.php:42"}}
```

Даты, перечисления, `JsonSerializable` и `Stringable` становятся читаемыми значениями, прочие
объекты — `[object ClassName]`. Некорректный UTF-8 заменяется, вложенность глубже 5 уровней
обрезается, поэтому запись не ломается ни на каких данных.

Общий контекст добавляется ко всем записям, контекст самой записи перекрывает его ключи:

```php
Log::channel()->withContext(['request' => $requestId]);   // одному каналу
Log::shareContext(['request' => $requestId]);             // всем каналам, и созданным позже
```

## Каналы

```php
Log::channel();                       // канал по умолчанию
Log::channel('telegram');             // канал из конфигурации, создаётся один раз
Log::stack(['daily', 'telegram']);    // временный канал из обработчиков нескольких каналов
```

Свой драйвер регистрируется через `extend()`. Фабрика получает конфигурацию канала и его имя и
возвращает `Logger` или обработчик:

```php
use Expansa\Log\Formatters\Line;
use Expansa\Log\Handlers\File;

Log::extend('short', fn (array $config, string $name) => new File($config['path'], $config['level'] ?? 'debug')
    ->setFormatter(new Line('H:i:s')));

Log::configure(['import' => ['driver' => 'short', 'path' => EX_STORAGE . 'logs/import.log']]);
```

## Обработчики и форматтеры

`Logger` можно собрать и без менеджера:

```php
use Expansa\Log\Logger;
use Expansa\Log\Handlers\File;
use Expansa\Log\Formatters\Line;

$logger = new Logger('import', [
    new File(EX_STORAGE . 'logs/import.log', 'info')->setFormatter(new Line('H:i:s')),
]);
```

| Обработчик     | Поведение                                                                        |
|----------------|----------------------------------------------------------------------------------|
| `File`         | Дописывает в файл, создаёт папку. Файл открывается один раз на запрос            |
| `RotatingFile` | Файл на день (`app-2025-01-31.log`), при открытии нового дня удаляет старые файлы |
| `Telegram`     | Сообщение через Bot API; таймаут 5 секунд, проверка SSL                          |
| `ErrorLog`     | `error_log()`: лог веб-сервера или файл из `error_log` в php.ini                 |

Каждая запись в Telegram — отдельный HTTP-запрос во время ответа, поэтому держите уровень высоким.
`chat_id` — число или `@username` канала. Сообщение экранируется и обрезается до 4096 символов.

Свой обработчик наследует `Handlers\AbstractHandler` и реализует `handle(LogRecord $record): bool`,
свой форматтер — `Formatters\AbstractFormatter` и `format(LogRecord $record): string`.
`normalize()` и `toJson()` базового форматтера безопасно превращают контекст в JSON.

Если обработчик выбросил исключение (диск заполнен, нет прав на папку), приложение продолжает
работу, остальные обработчики канала получают запись, а сообщение об ошибке и текст записи
уходят в `error_log()`.

## Исправленные ошибки

- фасад `Log` создавал `Logger` без обработчиков, записи никуда не попадали;
- `LogManager` требовал несуществующий `Container` и не мог быть создан;
- контекст `withContext()` не добавлялся к записям, плейсхолдеры `{key}` не заменялись;
- `Handlers\RotatingFile` игнорировал `maxFiles`: старые файлы не удалялись;
- `Handlers\Telegram` отключал проверку SSL, не имел таймаута, всегда возвращал `true`, не
  принимал `@username` канала, а неэкранированный `<` в сообщении ломал HTML-разметку;
- форматтер изменял общую запись, и следующий обработчик получал уже изменённый контекст;
- из исключения записывались только файл, строка и код, без класса и сообщения;
- ошибка обработчика молча терялась;
- `shareContext()` не применялся к каналам, созданным после вызова.

## Производительность

`php tests/benchmarks/Log.php [--baseline=<git ref>]` сравнивает с версией пакета из коммита,
по умолчанию `HEAD`. Запись в файл, мкс на запись:

| Случай                   | До      | После | Ускорение |
|--------------------------|--------:|------:|----------:|
| Уровень ниже порога      |    0.81 |  0.22 |      3.7x |
| Сообщение                |  422.0  |  16.0 |     26.4x |
| Сообщение с контекстом   |  520.3  |  19.8 |     26.3x |

Основной выигрыш — файл открывается один раз, а не на каждую запись. Запись ниже уровня всех
обработчиков стоит одно сравнение: запись не создаётся, плейсхолдеры не заменяются.
