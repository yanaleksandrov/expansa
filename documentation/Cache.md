# Введение

Cache — простое хранилище пар ключ/значение с поддержкой групп (namespace) и времени жизни
записи (TTL). Основной сценарий использования — не пересчитывать/не запрашивать заново то, что
уже было получено раньше: результат тяжёлого запроса к БД, ответ внешнего API, вычисленное
значение и т.д.

Всё взаимодействие идёт через фасад `Cache`, который сам решает, какой провайдер (реализация
хранилища) использовать. По умолчанию это `Expansa\Cache\Providers\Memory` — хранилище в памяти
текущего процесса.

```php
use Expansa\Facades\Cache;

Cache::set('key', 'value');
Cache::get('key'); // 'value'
```

## Группы

Второй параметр большинства методов — группа (`'default'`, если не указана). Группа — это
пространство имён: один и тот же ключ в разных группах — это разные записи, а `forget('', $group)`
позволяет очистить сразу всю группу, не перечисляя ключи вручную.

```php
Cache::set('123', $post, 'posts');
Cache::set('123', $user, 'users'); // не конфликтует с 'posts'

Cache::forget('', 'posts'); // очищает только группу 'posts'
```

## Добавление и чтение

`add()` записывает значение, только если ключа ещё нет (или он уже истёк) — повторный вызов с тем
же ключом молча вернёт то, что уже лежит в кэше, не перезаписывая его. `set()`, наоборот, всегда
перезаписывает значение и сбрасывает любой прежний TTL.

```php
Cache::add('key', 'first');
Cache::add('key', 'second'); // 'first' — add() не перезаписывает существующий ключ

Cache::set('key', 'second'); // перезаписывает безусловно
```

`get()` умеет лениво вычислять значение через callback, если ключа нет — результат callback тут
же сохраняется через `add()`, так что повторные вызовы `get()` больше не выполняют callback:

```php
$posts = Cache::get('recent', 'posts', function () {
    return Post::query()->orderByDesc('id')->limit(10)->get();
});
```

`pull()` — это `get()` с последующим `forget()`: прочитать значение и сразу удалить его из кэша.

## Время жизни записи (TTL)

По умолчанию запись живёт вечно (пока её не удалят явно или не вытеснит лимит на группу). Чтобы
ограничить срок жизни, передайте `$expiry` четвёртым параметром в `add()` — абсолютную дату
(`DateTime`) или относительную строку, которую понимает конструктор `DateTime`:

```php
use DateTime;

Cache::add('token', $value, 'auth', new DateTime('+15 minutes'));
Cache::add('token', $value, 'auth', '+15 minutes'); // эквивалентно
```

Как только срок истёк, запись перестаёт быть видимой для `get()`/`add()` — как будто её никогда
не было, независимо от используемого провайдера.

## Счётчики

`increase()`/`decrease()` изменяют числовое значение на месте и возвращают `bool` — успех операции,
а не новое значение. Работают только с уже существующим числовым значением; для нечислового или
отсутствующего ключа вернут `false`, ничего не создавая.

```php
Cache::set('views', 0, 'post-42');
Cache::increase('views', 1, 'post-42');
Cache::decrease('views', 1, 'post-42');
```

## Отложенная запись

`suspend()` временно блокирует `add()` для конкретного ключа на время выполнения callback — полезно,
чтобы защититься от повторного (рекурсивного) наполнения кэша одним и тем же ключом, пока идёт его
первое построение:

```php
Cache::suspend(function () {
    // пока выполняется этот callback, Cache::add('key', ..., 'group') будет возвращать false
}, 'key', 'group');
```

## Провайдеры

Провайдер — конкретная реализация хранилища, спрятанная за одним и тем же контрактом
`Expansa\Cache\Contracts\Provider`. Фасад `Cache` всегда резолвится в `Memory` — чтобы явно
использовать другой провайдер, создайте его экземпляр самостоятельно вместо обращения через фасад.

| Провайдер | Хранилище | Переживает конец процесса | TTL | Очистка всей группы |
|---|---|---|---|---|
| `Memory` | статический массив в PHP-процессе | нет | проверяется вручную при чтении | да, напрямую |
| `Database` | таблица `cache` | да | проверяется вручную при чтении | да, напрямую (`LIKE`) |
| `File` | файлы на диске | да | проверяется вручную при чтении | да, напрямую (удаление каталога группы) |
| `APCu` | общая память процесса (все воркеры на машине) | да, пока жив веб-сервер | нативный (сервер сам удаляет ключ) | да, но не удаляет физически — версионирование |
| `Redis` | Redis-сервер | да | нативный (сервер сам удаляет ключ) | да, через `KEYS`+`DEL` |
| `Memcached` | Memcached-сервер | да | нативный (сервер сам удаляет ключ) | да, но не удаляет физически — см. ниже |

## Какой провайдер выбрать

**`Memory`** — когда кэш нужен только в рамках одного запроса/процесса: не выполнять один и тот же
тяжёлый запрос дважды за один HTTP-запрос, или в долгоживущем процессе вроде `Scheduler::work()`,
которому не нужно ничего сохранять между перезапусками. Самый быстрый и не требует никакой
инфраструктуры, но данные пропадают вместе с процессом — для обычного PHP-FPM запроса это значит
"пропадают в конце запроса", то есть между разными запросами пользователей кэш не переиспользуется.

**`Database`** — когда кэш должен пережить конец запроса и перезапуск процесса, но заводить ради
этого отдельную инфраструктуру (Redis/Memcached) не хочется или не на чем: БД и так уже есть.
Медленнее остальных персистентных вариантов, так как каждое обращение — это запрос к БД, и создаёт
дополнительную нагрузку на неё же — не подходит для очень "горячих" ключей, которые читаются на
каждый запрос. Разумный выбор по умолчанию для небольших/средних проектов без Redis/Memcached под
рукой.

**`File`** — тот же сценарий, что и `Database` (нужна персистентность, но нет Redis/Memcached), но
когда не хочется нагружать БД лишними записями или таблица `cache` недоступна/неудобна. Не требует
ни расширений, ни отдельного сервера — только доступную на запись директорию, поэтому это самый
"дешёвый" по инфраструктуре персистентный вариант. Медленнее Redis/Memcached (каждое обращение — это
файловая операция) и не подходит, если приложение крутится на нескольких серверах без общей
файловой системы между ними (каждый сервер будет видеть свой независимый кэш).

**`APCu`** — когда нужен кэш, общий для всех воркеров PHP-FPM на одной машине, без сети и без
отдельного сервера: практически так же быстро, как `Memory`, но переживает конец запроса. Требует
`ext-apcu`. Ограничение — общая память процесса конечна и настраивается (`apc.shm_size`), а сам кэш
не покидает пределы одной машины: для нескольких серверов приложения он не подойдёт (каждый увидит
свою копию), в отличие от `Redis`/`Memcached`. Как и у `Memcached`, `increase()`/`decrease()` не
сохраняют TTL записи — у APCu тоже нет способа прочитать оставшийся срок жизни ключа.

**`Redis`** — когда важна скорость чтения/записи между запросами и/или кэш должен быть общим для
нескольких серверов приложения (шаренный кэш за балансировщиком). Требует поднятый Redis-сервер и
`ext-redis`. Из персистентных вариантов — самый функционально полный: нативный TTL и честная очистка
целой группы без побочных эффектов (`KEYS`+`DEL`), плюс `TTL` для сохранения срока жизни при
`increase()`/`decrease()`.

**`Memcached`** — тот же сценарий использования, что и `Redis` (быстрый общий кэш между процессами
и серверами), но с более скромным набором возможностей: очистка группы не удаляет данные физически
(счётчик версии — см. ниже), а `increase()`/`decrease()` не сохраняют TTL записи. Имеет смысл, если
Memcached уже есть в инфраструктуре (например, у хостинга он есть, а Redis — нет), либо интересно
только простое key/value-кэширование без частой очистки целых групп и без счётчиков с TTL. При
равном выборе между Redis и Memcached — предпочтительнее Redis: он строго функциональнее при
сопоставимой стоимости эксплуатации.

## Производительность

Ориентировочное сравнение скорости `set()`/`get()` на одну операцию. `Memory` и `File` измерены
здесь же (`php cache_bench.php`, Windows, NVMe SSD, PHP 8.4 без JIT) — абсолютные цифры сильно
зависят от железа/ОС/диска, важен скорее порядок величины и относительная разница между
провайдерами. Для `Database`/`APCu`/`Redis`/`Memcached` в этом окружении нет ни поднятой БД, ни
установленных расширений — цифры для них не измерены, а даны по общеизвестным характеристикам этих
хранилищ, как ориентир для порядка величины, а не гарантия.

| Провайдер | `set()` | `get()` (попадание) | Основной источник задержки |
|---|---|---|---|
| `Memory` | ~6.8 млн оп/с (измерено) | ~9 млн оп/с (измерено) | доступ к массиву в той же памяти процесса |
| `APCu` | сотни тыс. – единицы млн оп/с (не измерено) | сотни тыс. – единицы млн оп/с (не измерено) | доступ к общей памяти + блокировка |
| `Redis` | десятки – сотни тыс. оп/с (не измерено) | десятки – сотни тыс. оп/с (не измерено) | круговой обход по TCP/сокету до сервера |
| `Memcached` | десятки – сотни тыс. оп/с (не измерено) | десятки – сотни тыс. оп/с (не измерено) | круговой обход по TCP/сокету до сервера |
| `Database` | сотни – единицы тыс. оп/с (не измерено) | тысячи – десятки тыс. оп/с (не измерено) | сетевой запрос + разбор SQL на каждый вызов |
| `File` | ~1.5 тыс. оп/с (измерено) | ~26 тыс. оп/с (измерено) | `set()`: `mkdir`/временный файл/`rename` на каждый вызов; `get()`: одно открытие файла |

Из измеренного заметен разрыв на четыре порядка между `Memory` и `File`, поэтому `File` не годится
для по-настоящему "горячих" ключей — только для случаев, где важна персистентность, а частота
обращений к конкретному ключу невысокая. Расхождение `File`: `set()` намного дороже `get()`, потому
что пишет через `mkdir` + временный файл + `rename()`, а чтение — это одно открытие уже существующего
файла.

### Memory

Провайдер по умолчанию. Данные живут только в статических свойствах PHP-класса, то есть не
переживают конец процесса (для типичного PHP-FPM запроса — конец запроса). Есть лимит в 5000
записей на группу (`Memory::MAX_ENTRIES_PER_GROUP`) — при превышении вытесняется самая старая
запись (FIFO), чтобы долгоживущий процесс (например, `Scheduler::work()`) не рос бесконечно.

### Database

Хранит записи в таблице `cache` (`key`, `value`, `expiry_at`) — переживает перезапуск процесса.
Поскольку в таблице нет колонки группы, группа и ключ склеиваются в один физический ключ
(`"группа:ключ"`). Значение сериализуется через `serialize()`/`unserialize()`.

```php
use Expansa\Cache\Providers\Database;

$cache = new Database();
$cache->add('key', $value, 'group', '+1 hour');
```

`purgeExpired()` удаляет разом все просроченные строки независимо от группы — не вызывается
автоматически, подключите её вызов в задачу `Scheduler`, если таблица должна регулярно
самоочищаться от накопившихся просроченных записей.

### File

Хранит каждую запись отдельным файлом на диске: один каталог на группу, один файл на ключ (имя —
`sha1($key) . '.cache'`, чтобы произвольный ключ всегда был безопасным именем файла). По умолчанию
использует каталог `EX_PATH . 'storage/cache/'`, но его можно переопределить:

```php
use Expansa\Cache\Providers\File;

$cache = new File(); // EX_PATH . 'storage/cache/'
$cache = new File('/var/cache/myapp'); // свой каталог

$cache->add('key', $value, 'group', '+1 hour');
```

Запись пишется через временный файл с последующим `rename()`, поэтому читающий процесс никогда не
увидит наполовину записанный файл. `forget('', $group)` удаляет каталог группы целиком — не оставляет
"осиротевших" файлов, в отличие от версионирования у `Memcached`. `purgeExpired()` обходит все группы
и удаляет файлы с истёкшим сроком — как и у `Database`, не вызывается автоматически.

### APCu

Требует расширение `ext-apcu`, никакого клиента создавать не нужно — оно работает через глобальные
функции (`apcu_fetch()`, `apcu_store()` и т.д.), напрямую с общей памятью текущего сервера:

```php
use Expansa\Cache\Providers\Apcu;

$cache = new Apcu();
$cache->add('key', $value, 'group', '+1 hour');
```

TTL — нативный, как у Redis/Memcached. У APCu, как и у Memcached, нет дешёвого способа перечислить
ключи, поэтому очистка группы устроена так же — через счётчик версии в физическом ключе
(`"группа:vN:ключ"`): `forget('', $group)` увеличивает счётчик, старые записи становятся
недостижимыми и вытесняются самим APCu, когда закончится место в общей памяти.

### Redis

Требует установленное расширение `ext-redis` и уже подключённый клиент — соединение провайдер сам
не открывает:

```php
use Expansa\Cache\Providers\Redis;

$redis = new \Redis();
$redis->connect('127.0.0.1', 6379);

$cache = new Redis($redis);
$cache->add('key', $value, 'group', '+1 hour');
```

TTL — нативный: Redis сам удаляет запись по истечении срока, никакой ручной проверки при чтении не
требуется. Очистка всей группы выполняется через `KEYS "группа:*"` + `DEL` — подходит для кэшей
разумного размера; для группы из миллионов ключей замените на постраничный `SCAN` в этом методе.

### Memcached

Требует `ext-memcached` и уже подключённый клиент, как и `Redis`:

```php
use Expansa\Cache\Providers\Memcached;

$memcached = new \Memcached();
$memcached->addServer('127.0.0.1', 11211);

$cache = new Memcached($memcached);
$cache->add('key', $value, 'group', '+1 hour');
```

TTL тоже нативный. Но у Memcached нет команды перечисления ключей, поэтому очистка всей группы
устроена иначе: у каждой группы есть счётчик версии, зашитый в физический ключ
(`"группа:vN:ключ"`). `forget('', $group)` увеличивает этот счётчик — старые записи не удаляются
физически, а становятся недостижимыми и рано или поздно вытесняются самим Memcached (LRU) или
истекают по собственному TTL. Также `increase()`/`decrease()` здесь не сохраняют прежний TTL записи
(в отличие от остальных трёх провайдеров) — у Memcached нет команды прочитать оставшийся TTL ключа.

## Свой провайдер

Любое хранилище можно подключить, реализовав `Expansa\Cache\Contracts\Provider`:

```php
use Expansa\Cache\Contracts\Provider;
use DateTime;

class MyProvider implements Provider
{
    public function add(string $key, mixed $value, string $group = 'default', DateTime|string|null $expiry = null): mixed { /* ... */ }
    public function set(string $key, mixed $value, string $group = 'default'): mixed { /* ... */ }
    public function get(string $key, string $group = 'default', ?callable $callback = null): mixed { /* ... */ }
    public function pull(string $key, string $group = 'default'): mixed { /* ... */ }
    public function suspend(callable $callback, string $key, string $group = 'default'): void { /* ... */ }
    public function forget(string $key = '', string $group = 'default'): bool { /* ... */ }
    public function increase(string $key, int|float $amount = 1, string $group = 'default'): bool { /* ... */ }
    public function decrease(string $key, int|float $amount = 1, string $group = 'default'): bool { /* ... */ }
}
```
