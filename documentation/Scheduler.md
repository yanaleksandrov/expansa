# Введение

Планировщик запускает периодические задачи: PHP-замыкания, PHP-скрипты и shell-команды. Расписание
описывается CRON-выражением или fluent-методами (`daily()`, `hourly()`, `monday()`…). Весь пакет
находится в `Expansa\Scheduler`:

| Класс                             | Назначение                                                        |
|-----------------------------------|-------------------------------------------------------------------|
| `Scheduler`                       | Очередь задач, запуск наступивших, результаты, лог и конфигурация |
| `Job`                             | Задача: команда, расписание, условия, вывод, блокировка           |
| `CronExpression`                  | Разбор CRON-выражения, `isDue()`, следующая и предыдущая даты     |
| `Commands\Run`                    | Консольная команда `schedule:run`                                 |
| `Exceptions\InvalidExpression`    | CRON-выражение или его часть не разбирается                       |
| `Exceptions\InvalidInterval`      | Значение метода расписания вне диапазона: `hourly(60)`            |
| `Exceptions\ScriptNotFound`       | Скрипта задачи `php()` нет                                        |
| `Exceptions\InvalidConfiguration` | `email()` без почтового колбэка в `configure()`                   |
| `Exceptions\EmailNotSent`         | Колбэк не отправил письмо с выводом                               |

Упавшая задача попадает в `$scheduler->failedJobs` объектом со свойствами `job` и `exception`
(класс `Internal\FailedJob` внутренний: по имени на него не ссылаются).

Планировщик сам по себе ничего не запускает: его нужно вызывать **раз в минуту** системным cron'ом
(команда `php artisan schedule:run`) или держать запущенным через `work()`.

Пакет — форк [peppeocchi/php-cron-scheduler](https://github.com/peppeocchi/php-cron-scheduler) и
[dragonmantank/cron-expression](https://github.com/dragonmantank/cron-expression), переписанный под
PHP 8.4. Отличия от оригиналов перечислены в разделе [Отличия от оригинальных библиотек](#отличия-от-оригинальных-библиотек).

## Быстрый старт

```php
use Expansa\Scheduler\Scheduler;

$scheduler = new Scheduler();

$scheduler->call(fn () => cleanupSessions())->daily('03:00');
$scheduler->php(EX_PATH . 'scripts/sitemap.php')->hourly(15);
$scheduler->raw('gzip', ['-9', '/var/log/app.log'])->sunday('04:30');

$scheduler->run();
```

Запись в crontab сервера:

```
* * * * * php /path/to/scheduler.php > /dev/null 2>&1
```

`run()` проверяет все задачи на текущую минуту и выполняет наступившие. Секунды не учитываются:
задача с расписанием `30 10 * * *` выполнится при любом вызове между `10:30:00` и `10:30:59`.

## Команда schedule:run

Ядро и расширения добавляют задачи в слушателях хука `schedule`, он получает `Scheduler`:

```php
use Expansa\Facades\Hook;
use Expansa\Scheduler\Scheduler;

Hook::add('schedule', function (Scheduler $scheduler) {
    $scheduler->call(fn () => cleanupSessions())->daily('03:00')->onlyOne();
});
```

Запись в crontab сервера:

```
* * * * * cd /path/to/expansa-cms && php artisan schedule:run >> /dev/null 2>&1
```

Команда создаёт планировщик, передаёт его колбэку `schedule` и выполняет наступившие задачи. Каждая
выполненная задача выводится строкой `Done <задача>`, упавшая — в STDERR, с сообщением исключения.
Если упала хотя бы одна задача, команда завершается с кодом 1, и системный cron может сообщить об
ошибке.

Пакет не зависит от хуков: команду `Commands\Run` регистрирует `bootstrap.php` и передаёт колбэк,
который вызывает хук. Lock-файлы `onlyOne()` хранятся в `EX_STORAGE` — так задано в
`Scheduler::configure()`, см. [Конфигурация](#конфигурация).

```php
Terminal::addCommand(new Expansa\Scheduler\Commands\Run(
    schedule: fn (Scheduler $scheduler) => Hook::call('schedule', $scheduler),
));
```

Хук вызывается при каждом запуске команды, поэтому слушатель должен только объявлять задачи: всё
тяжёлое — внутри замыканий задач и условий `when()`.

## Типы задач

| Метод                                  | Что выполняется                                  | Аргументы                              |
|----------------------------------------|--------------------------------------------------|----------------------------------------|
| `call(callable $fn, array $args, $id)` | Любой callable в текущем процессе                | Строковые ключи — именованные аргументы |
| `php(string $script, $bin, $args, $id)`| Скрипт в отдельном процессе PHP                  | Экранируются, как у `raw()`            |
| `raw(string $command, $args, $id)`     | Shell-команда                                    | Экранируются через `escapeshellarg()`  |

Аргументы shell-команды: строковый ключ — это опция, значение `null` означает опцию без значения,
числовой ключ — позиционный аргумент.

```php
$scheduler->raw('backup', ['--force' => null, '--env' => 'prod', 'db.sql']);
// backup '--force' '--env' 'prod' 'db.sql'

$scheduler->call(fn (int $days, string $type) => pruneLogs($days, $type), ['type' => 'debug', 'days' => 30]);
```

`php()` по умолчанию использует текущий бинарник PHP (`PHP_BINARY`). Если скрипта нет, задача
не ставится в очередь и сразу попадает в `failedJobs` с `ScriptNotFound`.

Сама команда в `raw()` **не экранируется** — не подставляйте в неё пользовательские данные,
передавайте их через `$args`.

## Расписание

Каждый метод расписания заменяет предыдущий. Задача без расписания выполняется каждую минуту.

```php
$job->at('*/10 9-18 * * 1-5');   // CRON-выражение
$job->at('@daily');              // или алиас
```

| Метод                                     | Выражение          | Пример                         |
|-------------------------------------------|--------------------|--------------------------------|
| `everyMinute(?int $step)`                 | `* * * * *`        | `everyMinute(5)` → `*/5 * * * *` |
| `hourly(int $minute = 0)`                 | `m * * * *`        | `hourly(15)` → `15 * * * *`    |
| `daily($hour = 0, $minute = 0)`           | `m h * * *`        | `daily('09:05')` → `5 9 * * *` |
| `weekly($weekday = 0, $hour, $minute)`    | `m h * * w`        | `weekly(3, '10:30')`           |
| `monthly($month = '*', $day = 1, $hour, $minute)` | `m h d M *` | `monthly(day: 15)`             |
| `monday()` … `sunday()`                   | `weekly()`         | `friday(18)` → `0 18 * * 5`    |
| `january()` … `december()`                | `monthly()`        | `december(25, 8)`              |
| `date(DateTimeInterface\|string $date)`   | один раз           | `date('2030-05-06 07:08')`     |

Час можно передать строкой `H:i`, тогда минута берётся из неё. Значение `*` означает «любое».
Неверное значение (`hourly(60)`, `daily('25:00')`, `everyMinute(0)`) выбрасывает
`InvalidInterval`, неверное выражение в `at()` — `InvalidExpression`.

`date()` запускает задачу один раз: выражение совпадает с минутой даты каждый год, поэтому
задача дополнительно проверяет год. Последующий `at()` или другой метод расписания сбрасывает год.

## Синтаксис CRON

```
┌──────────── минута        0-59
│ ┌────────── час           0-23
│ │ ┌──────── день месяца   1-31, L, W, ?
│ │ │ ┌────── месяц         1-12 или JAN-DEC
│ │ │ │ ┌──── день недели   0-7 (0 и 7 — воскресенье) или MON-SUN, L, #, ?
* * * * *
```

| Символ | Значение                                                         | Пример                                  |
|--------|------------------------------------------------------------------|-----------------------------------------|
| `*`    | Любое значение                                                   | `* * * * *` — каждую минуту             |
| `,`    | Список                                                           | `0,30 * * * *` — в :00 и :30            |
| `-`    | Диапазон                                                         | `0 9-17 * * *` — каждый час с 9 до 17   |
| `/`    | Шаг от начала диапазона                                          | `5-20/5 * * * *` — :05, :10, :15, :20   |
| `L`    | Последний день месяца, или последний такой день недели           | `0 0 L * *`, `0 0 * * 5L`               |
| `W`    | Ближайший будний день, не выходя за пределы месяца               | `0 0 15W * *`                           |
| `#`    | N-й день недели месяца, от 1 до 5                                | `0 0 * * 5#2` — вторая пятница          |
| `?`    | «Не важно», только в одном из полей дня                          | `0 0 ? * 1`                             |

Если заданы **оба** поля дня (не `*` и не `?`), достаточно совпадения любого из них, как в
классическом cron: `0 0 13 * 5` — каждое 13-е число **и** каждая пятница.

Встроенные алиасы: `@yearly`, `@annually`, `@monthly`, `@weekly`, `@daily`, `@midnight`, `@hourly`.
Свои алиасы регистрируются глобально:

```php
use Expansa\Scheduler\CronExpression;

CronExpression::addAlias('@workdays', '0 9 * * 1-5');
$scheduler->call($report)->at('@workdays');

CronExpression::hasAlias('@workdays');     // true
CronExpression::forgetAlias('@workdays');  // встроенный алиас убрать нельзя: LogicException
```

## Условия и колбэки

```php
$scheduler->call($sync)
    ->hourly()
    ->when(fn () => isSyncEnabled())
    ->before(fn (Job $job) => error_log('start ' . $job->getId()))
    ->then(fn (?string $output, int $code) => error_log("done: $code"));
```

- `when(callable|bool)` — задача выполняется, только если условие строго равно `true`. Callable
  вызывается **в момент запуска** и только для наступившей задачи, поэтому тяжёлые проверки не
  выполняются каждую минуту.
- `before(callable)` — вызывается перед запуском, получает задачу.
- `then(callable, bool $runInBackground = false)` — вызывается после запуска, получает вывод и код
  выхода. Переводит задачу на передний план: у фоновой задачи нет вывода.

Пропущенная задача (условие ложно или предыдущий запуск ещё идёт) не попадает ни в выполненные,
ни в упавшие.

## Вывод

```php
$scheduler->raw('report')->daily()->inForeground()->output(EX_STORAGE . 'report.log', append: true);
```

| Метод                                  | Описание                                                        |
|----------------------------------------|-----------------------------------------------------------------|
| `output(array\|string $files, $append)`| Записать вывод в файлы, перезаписывая или дописывая              |
| `$job->output`                         | Вывод последнего запуска, `null` до запуска и у фоновой задачи   |
| `$job->returnCode`                     | Код выхода последнего запуска shell-команды на переднем плане    |
| `email(array\|string $emails)`         | Отправить вывод на почту, файлы вывода прикладываются            |

Вывод замыкания — всё, что оно напечатало, плюс возвращённая строка.

Письма отправляет колбэк `mailer` из [конфигурации](#конфигурация), каждому адресату отдельно:

```php
Scheduler::configure(
    email: [
        'subject'             => 'Отчёт планировщика',
        'body'                => null,   // по умолчанию тело письма — вывод задачи
        'ignore_empty_output' => true,   // не отправлять пустой вывод
    ],
    mailer: fn (string $to, string $subject, string $body, array $attachments) => Mail::send($to, $subject, $body, $attachments),
);

$scheduler->call($report)->daily()->email(['admin@example.com']);
```

`email()` переводит задачу на передний план. Без колбэка задача попадает в упавшие с
`InvalidConfiguration`, если колбэк вернул не `true` — с `EmailNotSent`. Отправитель — забота
колбэка: `bootstrap.php` передаёт `Mail::send()`.

## Защита от наложения

```php
$scheduler->raw('import')->everyMinute()->onlyOne();
```

`onlyOne(string $tempDir = '', ?callable $whenOverlapping = null)` создаёт lock-файл
`<id>.lock` на время выполнения. Пока он существует, следующие запуски пропускаются. Папка — `$tempDir`,
иначе `tempDir` из конфигурации, иначе системная временная.

`$whenOverlapping` получает время изменения lock-файла и возвращает `true`, чтобы всё равно
запустить задачу, например если lock остался от упавшего процесса:

```php
->onlyOne(whenOverlapping: fn (int $lockedAt) => time() - $lockedAt > 3600);
```

Lock снимается и тогда, когда задача выбросила исключение. У фоновой команды его удаляет сама
команда по завершении.

Имя lock-файла — идентификатор задачи: md5 команды с аргументами или места объявления замыкания
(файл и строка). Два замыкания на одной строке получат один идентификатор — задайте им `$id`.

## Фон и передний план

Shell-команды (`raw()`, `php()`) по умолчанию запускаются **в фоне**: планировщик не ждёт их
завершения. Для этого нужна POSIX-оболочка (`sh`, `tee`, `rm`), поэтому:

| Задача                                     | Где выполняется                  |
|--------------------------------------------|----------------------------------|
| Замыкание (`call()`)                       | всегда на переднем плане         |
| Команда после `inForeground()`, `then()`, `email()` | на переднем плане       |
| Команда на Windows                         | всегда на переднем плане         |
| Остальные команды                          | в фоне                           |

`run()` сначала запускает фоновые задачи, потом остальные, чтобы долгие задачи переднего плана не
задерживали старт фоновых. `compile()` показывает итоговую команду:

```php
$scheduler->raw('ls')->output('/tmp/ls.log')->onlyOne('/tmp')->compile();
// (ls | tee '/tmp/ls.log'; rm -f '/tmp/<id>.lock') > /dev/null 2>&1 &
```

## Запуск и результаты

```php
$executed = $scheduler->run();                   // сейчас
$executed = $scheduler->run(new DateTime('2025-01-01 10:30'));

$scheduler->executedJobs;                        // Job[]
$scheduler->failedJobs;                          // объекты со свойствами job и exception
$scheduler->getVerboseOutput();                  // 'text', 'html' или 'array'
$scheduler->flushJobs();                         // очистить очередь
```

Исключение или `Error` одной задачи не останавливает остальные: задача попадает в
`failedJobs`, а в лог записывается сообщение и описание задачи (команда или
`Closure файл:строка`).

Результаты накапливаются между вызовами `run()`. Если вызываете его несколько раз в одном процессе,
сбрасывайте их: `$scheduler->resetRun()->run()`.

### Постоянный процесс

```php
$scheduler->work([0, 30]);   // запуск на 0-й и 30-й секунде каждой минуты
```

`work()` не возвращается: спит до ближайшей из указанных секунд, сбрасывает результаты и вызывает
`run()`. Задача с расписанием `* * * * *` при `[0, 30]` выполнится дважды в минуту. Упавшие при
постановке в очередь задачи (`php()` без скрипта) видны только до первого запуска.

## Конфигурация

`Scheduler::configure()` — статический, `bootstrap.php` вызывает его в фазе `configure`:

```php
Expansa\Scheduler\Scheduler::configure(
    tempDir: EX_STORAGE,
    mailer: fn (string $to, string $subject, string $body, array $attachments) => Mail::send($to, $subject, $body, $attachments),
);
```

| Аргумент  | Тип        | Описание                                                               |
|-----------|------------|------------------------------------------------------------------------|
| `tempDir` | `string`   | Папка lock-файлов для `onlyOne()` без аргумента, иначе системная       |
| `email`   | `array`    | `subject`, `body`, `ignore_empty_output`, см. [Вывод](#вывод)          |
| `mailer`  | `?Closure` | Отправка письма, возвращает `true`; без него `email()`-задачи падают   |

Конфигурация применяется к задачам при постановке в очередь; повторный вызов заменяет её целиком.
Без вызова lock-файлы лежат в системной временной папке, а почта не отправляется.

## CronExpression

Выражение можно использовать без планировщика:

```php
use Expansa\Scheduler\CronExpression;

$cron = new CronExpression('0 9-17 * * 1-5');

$cron->isDue();                                     // сейчас
$cron->isDue('2025-01-03 10:00', 'Europe/Moscow');
$cron->getNextRunDate();                            // DateTime
$cron->getPreviousRunDate('2025-01-06 08:30');
$cron->getNextRunDate($date, nth: 2);               // пропустить два совпадения
$cron->getMultipleRunDates(5);                      // пять следующих дат
CronExpression::isValidExpression('0 25 * * *');    // false
$cron->parts;                                       // ['0', '9-17', '*', '*', '1-5']
$cron->maxIterationCount = 5000;                    // предел поиска даты, по умолчанию 1000
```

Даты считаются в часовом поясе переданной даты; для строки — в `$timeZone` или в поясе по
умолчанию. Переданный объект даты никогда не изменяется. Для невозможного выражения
(`0 0 30 2 *`) `getNextRunDate()` выбрасывает `RuntimeException`, а `getMultipleRunDates()`
возвращает пустой массив.

### Переход на летнее время

- Час, пропущенный при переводе часов вперёд, совпадает с часом после перевода: `30 2 * * *` в
  `America/New_York` 9 марта 2025 выполнится в `03:30`.
- Час, повторённый при переводе назад, совпадает **оба раза**: `30 1 * * *` 2 ноября 2025
  выполнится в `01:30 EDT` и в `01:30 EST`. Если повтор недопустим, проверяйте расписание в UTC:
  `$scheduler->run(new DateTime('now', new DateTimeZone('UTC')))`.

## Отличия от оригинальных библиотек

Исправленные ошибки dragonmantank/cron-expression:

- несортированные списки пропускали запуски: `0 5,2 * * *` от `01:00` давал `05:00` вместо `02:00`;
- шаг, равный диапазону, пропускал запуски: `*/59 * * * *` от `00:59` давал `01:59` вместо `01:00`;
- диапазоны дней недели с названиями, начинающиеся с воскресенья (`SUN-WED`), не совпадали никогда;
- `31W` в коротком месяце совпадал с днём следующего месяца;
- принимались неверные значения: `+5`, `1e1`, `*/-1`, `*/5/2`, `LW`;
- кэш переходов на летнее время пересчитывался при каждой проверке часа.

Исправленные ошибки php-cron-scheduler и прежней версии пакета:

- неверный namespace `Cron`, из-за которого пакет не загружался;
- `at()` и все интервалы падали на readonly-свойствах, а `hourly()`, `daily()` и другие — на
  `null` в проверке значений;
- `when()` вызывал условие при объявлении задачи, а не при запуске;
- lock-файл оставался навсегда, если задача выбросила исключение;
- `Error` задачи останавливал весь `run()`, пропущенные задачи считались выполненными;
- строковая команда, совпадающая с именем PHP-функции (`raw('date')`), вызывалась как функция;
- числовые ключи аргументов вызывали `TypeError`, пути файлов в `tee` и `rm` не экранировались;
- вывод shell-команды накапливался между запусками, `email()` ничего не отправлял;
- `work()` загружал процессор на 100% в пустом цикле, а результаты копились без ограничений;
- описание упавшего замыкания без класса вызывало ошибку.

## Производительность

`php tests/benchmarks/Scheduler.php` сравнивает форк с оригинальной библиотекой из `vendor/`
(устанавливается как dev-зависимость). 10 типичных выражений, PHP 8.4, мкс на все 10:

| Операция             | Оригинал | Форк  | Ускорение |
|----------------------|---------:|------:|----------:|
| `new CronExpression` |     77.1 |  52.0 |      1.5x |
| `isDue()`            |    855.7 |  22.2 |     38.6x |
| `getNextRunDate()`   |    871.3 | 534.0 |      1.6x |
| `getPreviousRunDate()` |  630.6 | 311.1 |      2.0x |

`isDue()` — это то, что `run()` вызывает для каждой задачи каждую минуту. Оригинал искал ближайшую
