## Правила кодинга

- CSS и JS правь в `src/`; `expansa-cms/dashboard/assets/` перезаписывается при билде.
- youla.js не меняй; если проблема в нём — напиши промпт для фикса в его проекте.
- PHP 8.4+, но производительность в приоритете.
- Бенчмаркай ключевые части, оставляй самый быстрый вариант без потери читаемости.
- Бета, не в проде: обновляй код без обратной совместимости.
- Именование, структура пакетов, добавление пакетов и обновление кода — [CONVENTIONS.md](CONVENTIONS.md).

## Комментарии

- Только то, что нельзя однозначно понять из кода; не пересказывай логику, предпочитай понятный код.
- Функции, методы, константы, свойства — `/** */`: описание 2–4 строки плюс `@param` и другие теги.
  У классов длина не ограничена. Остальное — `//`.
- `//` — всегда одна строка, только внутри функций и методов.
- Без подробных объяснений. CSS — не больше строки. В HTML комментариев нет.
- Поддерживай актуальность: описания устаревают вместе с кодом.

## Конструкторы: promotion + property hooks

Свойства, которые присваиваются из параметров конструктора, объявляй в его сигнатуре:

```php
public function __construct(

    /**
     * Cookie name.
     */
    public string $name {
        set {
            if (! preg_match('/^[A-Za-z0-9._-]+$/', $value)) {
                throw new CookieException('The "name" parameter value contains illegal characters.');
            }

            $this->name = $value;
        }
    },

    /**
     * Handlers used by the channel.
     *
     * @var Handler[]
     */
    array $handlers = [],

    public string $path = '' {
        set => $value === '' ? '/' : $value;
    },

    public bool $secure = false,
) {}
```

- Логика при установке: нет → обычное promoted property (без `set => $value`); одно выражение → `set =>`;
  условие, исключение, несколько действий → блок `set { }`. Не выноси проверку в тело конструктора,
  если она выражается hook'ом.
- Отдельно объявленное свойство не дублируй: visibility, тип, `readonly` и default переносятся в параметр.
- PHPDoc каждого параметра — прямо перед ним, а не общим блоком над конструктором; generic-типы
  (`Handler[]`) сохраняются в `@var`.
- Hook пишет прямо в `$this->prop`; дополнительное приватное свойство для хранения не создавай.
- Тело пустое → `) {}`. Логику, которая не выражается hook'ом (`setHandlers()`) или связывает
  несколько параметров, оставь в конструкторе.
- Форматирование: пустая строка после `(`, если есть PHPDoc; параметр — отдельным блоком, запятая
  после каждого; hook сразу после типа/значения.
- Семантика не меняется: visibility, `readonly`, типы и nullable, default, порядок параметров,
  валидация, нормализация, исключения и сообщения, PHPDoc, типы элементов массивов.

Ограничения PHP:

- У `readonly` hook'а быть не может: проверяй повторную запись в hook (`if (isset($this->name)) throw`)
  или оставь `readonly` без hook.
- Параметр promoted property принимает только тип свойства, не `set(A|B $value)`. Другие входные типы
  (`Level|int|string` для `Level`) нормализуются в теле конструктора.
- Массив свойства с hook не меняется по ссылке (`$this->items[] =`, `array_unshift`) — присваивай новый:
  `$this->handlers = [$handler, ...$this->handlers]`.
- PHPStan не видит инициализацию `readonly`-свойства внутри hook другого свойства.
- phpcs 3.x даёт ложные ошибки на hooks (см. CONVENTIONS, «Стиль кода»).
